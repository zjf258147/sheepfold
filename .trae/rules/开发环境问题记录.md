## 问题1：Docker 服务未运行

**日期**：2026-09-04

**现象**：执行 `docker compose up -d` 时报错 `failed to connect to the docker API`。

**根因**：Docker Desktop 未启动。

**解决**：放弃 Docker 部署方式，改为本地直接启动 MySQL + 后端 + 前端。

**涉及命令**：无

---

## 问题2：Docker 镜像拉取失败

**日期**：2026-09-04

**现象**：`docker pull mysql:5.7` 报错，镜像仓库 `hub-mirror.c.163.com` 无法连接。

**根因**：Docker 配置了国内镜像加速器（163），但该镜像源已失效。

**解决**：放弃 Docker 拉取 MySQL，改为使用本地已安装的 MySQL 5.7。

**本地 MySQL 路径**：`C:\Program Files\MySQL\MySQL Server 5.7\`

**涉及命令**：无

---

## 问题3：MySQL root 密码未知

**日期**：2026-09-04

**现象**：`mysql -u root` 提示 `Access denied`，无法直接连接。

**根因**：本地 MySQL 5.7 之前已安装并设置过 root 密码，但密码未被记录。

**解决方案**：
1. 尝试常见密码 `root`、`123456`、`password`、`admin`、空密码
2. 密码 `123456` 验证通过

**涉及命令**：
```bash
mysql -u root -p123456 -e "SELECT 'OK';"
```

**预防措施**：后续创建独立的 `ims` 用户，避免直接使用 root。

## 问题4：MySQL 服务无法注册为 Windows 服务

**日期**：2026-09-04

**现象**：`mysqld --install MySQL57` 报 `Install/Remove of the Service Denied!`。

**根因**：当前 PowerShell 没有管理员权限，无法注册 Windows 系统服务。

**解决方案**：直接前台启动 mysqld 进程，不注册为服务。

**涉及命令**：
```bash
& 'C:\Program Files\MySQL\MySQL Server 5.7\bin\mysqld.exe' --defaults-file='C:\ProgramData\MySQL\MySQL Server 5.7\my.ini' --console
```

**注意**：每次重启电脑后需要重新执行此命令启动 MySQL。

## 问题5：数据库和用户不存在

**日期**：2026-09-04

**现象**：启动后端时报数据库连接失败。

**根因**：MySQL 中没有 `ims` 数据库和 `ims` 用户。

**解决方案**：
```sql
CREATE DATABASE IF NOT EXISTS ims CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER IF NOT EXISTS 'ims'@'%' IDENTIFIED BY 'ims_pass';
CREATE USER IF NOT EXISTS 'ims'@'localhost' IDENTIFIED BY 'ims_pass';
GRANT ALL PRIVILEGES ON ims.* TO 'ims'@'%';
GRANT ALL PRIVILEGES ON ims.* TO 'ims'@'localhost';
FLUSH PRIVILEGES;
```

**涉及命令**：
```bash
mysql -u root -p123456 -e "CREATE DATABASE IF NOT EXISTS ims ..."
```

## 问题6：Alembic 迁移链断裂

**日期**：2026-09-04

**现象**：`alembic upgrade head` 报错 `KeyError: 'm7n8o9p0q1r2'`。

**根因**：`n8o9p0q1r2s3_add_change_reason_to_audit_log.py` 的 `down_revision` 指向 `m7n8o9p0q1r2`，但该 revision 对应的迁移文件（product_sku 新增字段）缺失。

**解决方案**：创建缺失的迁移文件 `m7n8o9p0q1r2_add_sku_fields_to_product_sku.py`，内容为新增 `sku_code`、`spec`、`sku_type` 三个字段。

**迁移链**：
```
l6m7n8o9p0q1 → m7n8o9p0q1r2 → n8o9p0q1r2s3 → o9p0q1r2s3t4 → p0q1r2s3t4u5 → q1r2s3t4u5v6
```

**涉及命令**：
```bash
cd backend && python -m alembic upgrade head
```

## 问题8：admin 用户不存在

**日期**：2026-09-04

**现象**：前端登录页面输入 `admin` / `admin123` 后提示"登录失败：用户名不存在"。

**根因**：Alembic 迁移脚本 `db50005be6c8_init_sys_user.py` 只创建了 `sys_user` 表结构，未插入初始管理员数据。

**解决方案**：手动通过 MySQL 插入 admin 用户：
```sql
INSERT INTO sys_user (username, password, nickname, role, status, created_at, updated_at)
VALUES ('admin', '{bcrypt_hash}', '管理员', 'ADMIN', 1, NOW(), NOW());
```

密码使用 bcrypt 加密，通过 Python 生成：
```python
import bcrypt
salt = bcrypt.gensalt()
hashed = bcrypt.hashpw('admin123'.encode('utf-8'), salt)
print(hashed.decode('utf-8'))
```

**预防措施**：后续考虑在 `main.py` 的 lifespan 中添加自动检查并创建 admin 用户的逻辑。

## 问题9：uv 包管理工具未安装

**日期**：2026-09-04

**现象**：`uv run uvicorn main:app` 报 `'uv' 不是内部或外部命令`。

**根因**：开发说明中指定使用 `uv` 作为 Python 包管理器，但当前环境未安装。

**解决方案**：改用标准 Python 命令：
```bash
# 原命令
uv run uvicorn main:app --reload --host 0.0.0.0 --port 8000
# 替代命令
python -m uvicorn main:app --reload --host 0.0.0.0 --port 8000
```

**涉及命令**：无

## 当前环境启动完整流程

```bash
# 1. 启动 MySQL（每次开机后需要）
& 'C:\Program Files\MySQL\MySQL Server 5.7\bin\mysqld.exe' --defaults-file='C:\ProgramData\MySQL\MySQL Server 5.7\my.ini' --console

cd ims-main/backend
python -m uvicorn main:app --reload --host 0.0.0.0 --port 8000

# 3. 启动前端（新终端）
cd ims-main/frontend
npm run dev

# 4. 浏览器访问
http://localhost:5173
```
