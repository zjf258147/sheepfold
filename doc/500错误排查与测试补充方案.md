## 第1章 背景与问题分析

### 1.1 500 错误的本质

**500 = Internal Server Error（服务器内部错误）**，即后端代码抛了未捕获的异常。

| 常见原因 | 示例 |
|---------|------|
| 数据库查询出错 | SQL 语法错、字段不存在、外键约束 |
| 空指针/NoneType | 查不到数据却直接取属性 |
| 参数类型不匹配 | 前端传字符串，后端要整数 |
| 序列化失败 | Pydantic 校验不通过 |
| 权限未拦截 | 用户角色不该访问，但代码没拦住 |
| 懒加载失败 | SQLAlchemy session 关闭后访问关联对象 |

**关键**：500 是后端崩溃，不是前端问题。前端只是调了一个会崩的接口。

### 1.2 为什么现有检查没查出来

| 检查类型 | 为什么漏了 | 文件 |
|---------|-----------|------|
| **契约测试** | 只测了 API 的"正常路径"，参数是精心构造的，没测前端实际传的参数组合 | `tests/contract/` 21文件 |
| **场景测试** | 只测了 10 条核心业务流程（S001-S010），没覆盖所有页面 | `tests/scenario/` |
| **边界测试** | 测了空字段/超长/特殊字符，但没测"某种数据状态下"的边界 | `test_edge_cases.py` |
| **E2E 冒烟测试** | 只测了登录页、路由守卫、控制台错误，没有遍历所有页面 | `tests/e2e/test_smoke.py` |
| **跨浏览器测试** | 只测了登录页渲染 | `tests/e2e/test_cross_browser.py` |

**核心缺口**：没有"遍历所有页面 + 所有角色 + 所有数据状态"的冒烟测试。

### 1.3 现有全局异常处理器状态

[main.py:L89-L96](file:///c:/Users/25075/Desktop/IMS生产物料与产品追溯管理系统/ims-main/backend/main.py#L89-L96) 已存在全局异常处理器：

```python
@app.exception_handler(Exception)
async def global_exception_handler(request: Request, exc: Exception):
    logger.exception(f"未处理异常 [{request.method} {request.url}]: {exc}")
    return JSONResponse(
        status_code=500,
        content={"code": 500, "msg": "服务器内部错误", "data": None},
    )
```

**已做**：捕获未处理异常 + 记录日志 + 返回统一格式。

**缺失**：返回的 `msg` 是固定的"服务器内部错误"，没有 `str(exc)` 详情。DEBUG 模式下应返回具体错误信息以便快速定位。

**确认**：配置变量为 `settings.DEBUG`（定义于 [config.py:L8](file:///c:/Users/25075/Desktop/IMS生产物料与产品追溯管理系统/ims-main/backend/app/core/config.py#L8)，类型 `bool`，默认 `False`）。

## 第3章 执行计划（9 步）

```
第1步 → 描述当前500的具体页面和操作

第4步 → 对每个500看日志，输出根因清单
第5步 → 按根因分类，逐个修复（锁范围）
第6步 → 改进全局异常处理器（加 str(exc) 详情）

### 3.1 修复阶段约束（第5步）

| 约束项 | 规则 |
|--------|------|
| 不改公共组件 | TablePro / SearchForm 等不动 |
| 不改数据库结构 | 不新增字段、不改表结构 |
| 不改权限逻辑 | 路由守卫、角色判断不动 |
| 不改 API 返回格式 | 保持现有响应结构 |
| 一次不超过 3 个文件 | 单次改动范围可控 |
| 同一根因一次修 | 多个 500 同根因 → 合并为一次修复 |

### 3.2 修复流程

```
第1步：只复现，不改代码

## 第4章 API 全量冒烟测试设计

### 4.1 测试目标

**验证不返回 500**（非验证返回 200）：

| 状态码 | 判断 | 说明 |
|:---:|:---:|------|
| 200 | ✅ 通过 | 正常返回 |
| 400 | ✅ 通过 | 参数错误但后端正确处理 |
| 403 | ✅ 通过 | 权限不足但正确处理 |
| 404 | ✅ 通过 | 资源不存在但正确处理 |
| 422 | ✅ 通过 | 校验失败但正确处理 |
| **500** | **❌ 失败** | **后端崩溃，需修复** |

### 4.2 三类端点处理方式

| 类型 | 说明 | 示例 | 处理方式 |
|------|------|------|---------|
| **A** | 无参数 GET | `GET /api/v1/stations` | 直接请求，无需 fixture |
| **B** | 需路径参数 | `GET /api/v1/incoming/123` | fixture 创建数据 → 取 id → 请求 |
| **C** | 需 body 的写操作 | `POST /api/v1/stations` | 用最小合法 body 请求 |

### 4.3 覆盖所有 HTTP 方法

| 方法 | 示例 | 处理方式 |
|------|------|---------|
| **GET** | `GET /api/v1/stations` | A 类直接请求；B 类用 fixture |
| **POST** | `POST /api/v1/stations` | C 类，最小合法 body |
| **PUT** | `PUT /api/v1/stations/1` | B+C 类，fixture 创建后请求 |
| **DELETE** | `DELETE /api/v1/stations/1` | B 类，fixture 创建后请求 |

## 第5章 前端路由遍历测试设计

### 5.1 测试目标

用 Playwright 登录后遍历所有 23 个页面，检查每个页面的所有网络请求中是否出现 500。

### 5.2 关键设计点

| 问题 | 解决方案 |
|------|---------|
| 未登录访问会跳转登录页 | 先用 `admin` 登录，获取 token/cookie |
| 部分页面 admin 也无权限 | 路由配置中 `roles` 不含 admin 但 `!auth.isAdmin` 判断会放行 admin |
| 页面加载是异步的 | 等待 `networkidle` 或关键元素出现 |
| 500 可能来自子请求 | 监听所有 response（`page.on("response")`），不只主请求 |
| 参数路由需具体 ID | 用 fixture 或 `page.goto` 带已有数据 ID |

### 5.4 admin 角色权限分析

根据 [router/index.js](file:///c:/Users/25075/Desktop/IMS生产物料与产品追溯管理系统/ims-main/frontend/src/router/index.js#L69-L72) 路由守卫逻辑：

## 第6章 全局异常处理器改进

### 6.1 当前代码

[main.py:L89-L96](file:///c:/Users/25075/Desktop/IMS生产物料与产品追溯管理系统/ims-main/backend/main.py#L89-L96)

### 6.2 改进后代码

```python
@app.exception_handler(Exception)
async def global_exception_handler(request: Request, exc: Exception):
    """捕获未处理的异常，返回统一错误格式并记录日志。"""
    logger.exception(f"未处理异常 [{request.method} {request.url}]: {exc}")
    detail = str(exc) if settings.DEBUG else "服务器内部错误"
    return JSONResponse(
        status_code=500,
        content={"code": 500, "msg": detail, "data": None},
    )
```

**改动量**：仅 1 行差异（`detail = str(exc) if settings.DEBUG else "服务器内部错误"`），替换原有的固定字符串。

**影响范围**：
- 不改 API 格式（仍返回 `{code, msg, data}`）
- 不改数据库结构
- 不影响现有测试（现有测试不检查 `msg` 的具体值）
- DEBUG=False 时行为与现在完全一致

### 6.3 验证方式
