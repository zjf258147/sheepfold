## 2026-09-07：IMS 应用性能优化方案

### 背景

用户提出引入 Engram 做记忆管理以提速增效，经分析后确定："记忆管理"提速的核心应聚焦于 **IMS 系统本身的应用性能优化**，而非引入外部记忆工具。

### 优化目标

| 优化方向 | 适用场景 | 预期提速 |
|----------|----------|:--------:|
| Redis 缓存 | 高频查询（SN 搜索、库存查询、下拉选项） | 3-10x |
| MySQL 查询优化 | 索引优化、慢查询治理 | 2-5x |
| 前端虚拟滚动 | 列表数据量大时（原材料库存、BOM 清单） | 显著提升渲染 |
| API 游标分页 | 大数据量列表 | 减少 DB 压力 |

### 设计思路

采用 **四层优化架构**，从上到下覆盖：

```
┌──────────────┐
│  前端虚滚层   │  v-infinite-scroll + 游标分页
├──────────────┤
│  缓存层       │  Redis (生产) / MemoryCache (开发)
├──────────────┤
│  API 分页层   │  偏移分页 + 游标分页双模式
├──────────────┤
│  MySQL 优化层  │  连接池 + 查询超时 + 事务隔离
└──────────────┘
```

### 关键代码路径

| 文件 | 功能 | 说明 |
|------|------|------|
| `backend/app/core/cache.py` | 缓存抽象层 | Redis + MemoryCache 双模式，`cached` 装饰器 |
| `backend/app/core/config.py` | Redis 配置 | `REDIS_ENABLED`/`REDIS_HOST`/`REDIS_PORT` |
| `backend/app/db/database.py` | 连接池优化 | `pool_size=10` + `max_execution_time=30s` |
| `backend/app/schemas/common.py` | 游标分页 Schema | `CursorPageResult` 模型 |
| `backend/app/service/inventory_service.py` | 游标分页查询 | `get_items_cursor()` 方法 |
| `backend/app/api/inventory.py` | 游标分页端点 | `/api/v1/inventory/items/cursor` |
| `backend/app/service/product_service.py` | 分类缓存 | `CATEGORY_CACHE_KEY` TTL=600s |
| `backend/app/service/partner_service.py` | 单位分组缓存 | `GROUP_CACHE_KEY` TTL=600s |
| `frontend/src/api/inventory.js` | 游标分页 API | `listItemsCursor()` 函数 |
| `frontend/src/views/inventory/InventoryDetail.vue` | 无限滚动 | `v-infinite-scroll` 模式切换 |
| `docker-compose.yml` | Redis 服务 | `redis:7-alpine` + 持久化 + 健康检查 |

### 技术选型理由

- **Redis 7 Alpine**：轻量、生产级、支持持久化（AOF）、LRU 淘汰策略
- **MemoryCache 降级**：本地开发无需安装 Redis，自动降级，零配置
- **游标分页**：基于主键 ID 降序 + Base64 编码 cursor，避免 `OFFSET` 大偏移量性能问题
- **Element Plus v-infinite-scroll**：官方内置指令，无需引入第三方虚拟滚动库

### 规范文档

详细规范已写入 `.trae/rules/project_rules.md` → **规则24：性能优化规范**（含 4 个子规范：Redis 缓存层、MySQL 查询优化、前端无限滚动、游标分页）

### 后续开发注意事项

1. 新增高频只读查询（SKU 列表、供应商列表）默认评估是否需要加缓存
2. 新增列表页面预计 >500 条时，同时提供普通分页和无限滚动两种模式
3. 新增列表数据量 >5000 条时，默认增加游标分页端点
4. 数据变更（增/改/删）时必须调用 `invalidate_cache()` 使缓存失效

## 2026-09-07：开发流程改进方案

### 背景

用户发现三个痛点：
1. "发现设计的页面有问题时，应该全局检查这一部分，而不是说啥改啥"
2. "每完成一个主线任务，先用 skill 检查，然后运行前后端预览"
3. "总是记录 bug、方案设计到对应的文档里"

### 解决方案

新增三个规则（已写入 `.trae/rules/project_rules.md`）：

| 规则 | 触发词 | 核心功能 |
|------|--------|----------|
| 规则25：全局检查 | "全局检查"、"全面检查" | 搜索模块所有相关文件 → 逐一检查 → 一致性调整 |
| 规则26：主线收尾 | "主线[字母]收尾" | 7 步自动检查：代码质量→异味→技术栈→浏览器→后端→前端→文档 |
| 规则27：文档同步 | "记录 Bug"、"记录方案" | 自动追加到对应文档（bug记录.md / 开发方案.md / 环境问题记录.md） |

### 文档映射

| 内容类型 | 对应文档 |
|----------|----------|
| Bug 修复 | `doc/bug记录.md` |
| 方案设计 | `doc/开发方案.md`（本文档） |
| 环境问题 | `doc/开发环境问题记录.md` |
| 主线完成 | `doc/主线[字母]_完成报告.md` |
