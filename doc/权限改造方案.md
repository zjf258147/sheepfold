# IMS 权限改造方案

> 版本：v1.0 | 制定日期：2026-09-20 | 状态：待执行
>
> 目标：所有角色都能查看业务模块，但只能编辑自己职责范围内的操作。
> 原则：查看全开放、编辑按操作、管理模块例外、前后端双校验。

---

## 一、前置决策

| # | 决策项 | 结论 |
|---|--------|------|
| 1 | 是否新增 GENERAL_MANAGER？ | 不新增，ADMIN 即总经理角色 |
| 2 | 审计日志、用户管理、系统设置是否全员可看？ | 仅 ADMIN |
| 3 | BOM 是否允许 WAREHOUSE 创建/编辑？ | 允许（沿用现有矩阵） |
| 4 | 报废申请是否允许 QUALITY、TEST_ENGINEER？ | 允许；报废审批仅 ADMIN |

---

## 二、核心设计原则

| # | 原则 | 说明 |
|---|------|------|
| 1 | 查看全开放 | 所有登录用户可查看业务列表、详情、导出 |
| 2 | 编辑按操作 | 新增/编辑/删除/审核/审批/状态变更按角色控制 |
| 3 | 管理模块例外 | 审计日志、用户管理、系统设置仅 ADMIN |
| 4 | 前端禁用+提示 | 无权限按钮显示但禁用，tooltip 提示"您的角色无此操作权限" |
| 5 | 后端严格校验 | 所有写接口必须加 `require_roles`，前端禁用不等于安全 |
| 6 | 操作级权限 | 同一模块不同操作可属于不同角色，不按模块一刀切 |
| 7 | 权限集中管理 | 前端统一 `canEdit()`，后端统一权限常量，不散落 |
| 8 | ADMIN 自动放行 | `require_roles` 对 ADMIN 直接放行 |

`stores/auth.js` 增加 `canEdit` 方法：

```js
import { PERMISSION_MAP } from '@/constants/permissions'

function canEdit(permissionKey) {
  if (isAdmin.value) return true
  const allowed = PERMISSION_MAP[permissionKey] || []
  return allowed.includes(role.value)
}
```

新建 `frontend/src/components/PermissionButton.vue`：

```vue
<template>
  <el-tooltip
    v-if="!hasPermission"
    content="您的角色无此操作权限"
    :disabled="!!$attrs.disabled && hasPermission"
  >
    <span>
      <el-button v-bind="$attrs" disabled>
        <slot />
      </el-button>
    </span>
  </el-tooltip>
  <el-button v-else v-bind="$attrs" @click="$emit('click')">
    <slot />
  </el-button>
</template>

<script setup>
import { computed } from 'vue'
import { useAuthStore } from '@/stores/auth'

const props = defineProps({
  permission: { type: String, required: true }
})

defineEmits(['click'])
const auth = useAuthStore()
const hasPermission = computed(() => auth.canEdit(props.permission))
</script>
```

### 5.3 菜单改造

`MainLayout.vue`：去掉 `roles` 过滤，所有菜单全显示。管理类菜单保留 `adminOnly`。

```js
// 改造前
const menus = computed(() => {
  return allMenus.filter((m) => {
    if (m.adminOnly && !auth.isAdmin) return false
    if (m.roles && !m.roles.includes(role) && !auth.isAdmin) return false
    return true
  })
})

// 改造后
const menus = computed(() => {
  return allMenus.filter((m) => {
    if (m.adminOnly && !auth.isAdmin) return false
    return true
  })
})
```

业务菜单去掉 `roles` 字段，仅管理菜单（settings/users/audit-logs）保留 `adminOnly`。

## 七、风险与应对

| # | 风险 | 应对 |
|---|------|------|
| 1 | 路由仍限制导致重定向 | 业务路由去掉 `meta.roles`，仅管理路由保留 |
| 2 | tooltip 在 disabled 按钮上失效 | 用 PermissionButton 外层 span 包裹 |
| 3 | 前后端权限键不一致 | 建立唯一权限字典，前后端同步维护 |
| 4 | 漏改某个写接口 | 用权限矩阵测试自动发现未覆盖接口 |
| 5 | 导出权限不统一 | 明确业务导出全员可用，审计导出仅 ADMIN |
| 6 | ADMIN 被误拦 | `require_permission` 对 ADMIN 直接放行 |
| 7 | 改造中途影响线上 | 分批改，每批跑全量测试后再合并 |
