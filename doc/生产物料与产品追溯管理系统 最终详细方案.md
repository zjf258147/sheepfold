# 敦临 IMS 生产物料与产品追溯管理系统 完整开发方案（V4.5）

> **所属单位**：西安敦临计量检测有限公司
> **系统简称**：敦临 IMS（DL-IMS）


## 第一章：系统总览

### 1.1 设计目标

**基石目标**：用一套系统完整替代 3 张 Excel（到货台账、出货台账、退货台账），实现 **“来料检测 → BOM生产准备 → 发货 → 异常退货（维修/再出货）→ 最终去向”** 全流程闭环管理。

**核心原则**：
- 唯一 SN 贯穿成品全生命周期
- 新旧 SN 强制关联（维修换码）
- 所有操作强制记录“谁、何时、改了什么、为什么”
- 权限最小化与职责分离
- 批次 + 可选 SN 双轨制管理原材料
- 复用 IMS 现有表结构（`partner`、`product_sku`、`inventory_item`、`audit_log`），保持数据一致性
- **物料编码（U9编码）与物料名称一一对应，作为物料主数据的核心标识**

### 1.2 物料编码与物料名称的对应关系

在 U9 系统中，每一个物料都有唯一的**物料编码**（如 `202-046`）和对应的**物料名称**（如 `148采集单元`）。两者是一一对应的关系。

| 物料编码（U9编码） | 物料名称 | 规格型号 | 单位 |
|-------------------|---------|---------|------|
| 202-046 | 148采集单元 | HD-AU906A | 套 |
| 202-018 | 115采集模块 | HD-AU902 | 套 |
| 306-058 | 工控机 | I7-6700（10T） | 台 |
| 307-052 | 接触式超声波传感器 | HD-S2112 | 只 |

**在系统设计中的体现：**

所有业务表（出货单、退货单、到货单等）中：
- 使用 `sku_id`（外键）关联 `product_sku` 表，保持数据关系
- 冗余存储 `sku_code`（物料编码）、`sku_name`（物料名称）、`spec`（规格）、`unit`（单位），确保历史数据一致性

### 1.3 四大业务主线

| 主线 | 名称 | 对应原 Excel | 核心功能 |
|------|------|-------------|----------|
| 主线A | 采购来料管理 | 物料到货记录台账 | 到货登记 → 来料检验 → 合格入库 / 退货供应商 |
| 主线B | 成品返厂维修管理 | 场站异常退货记录台账 | 退货登记 → 诊断 → 维修换新SN → 报废审批 → 再出货 |

## 第二章：物料主数据设计（核心基础）

### 2.1 `product_sku` 表改造（IMS 现有表）

在现有 `product_sku` 表基础上，新增和调整以下字段：

| 字段名 | 类型 | 长度 | 默认值 | 说明 |
|--------|------|------|--------|------|
| sku_code | VARCHAR | 50 | - | **物料编码（U9编码）** ，如 `202-046` |
| name | VARCHAR | 100 | - | **物料名称**，如 `148采集单元`（IMS原有字段，保留） |
| spec | VARCHAR | 100 | NULL | **规格型号**，如 `HD-AU906A`（新增） |
| unit | VARCHAR | 10 | NULL | 单位（IMS原有字段，保留） |
| sku_type | VARCHAR | 20 | 'FINISHED_GOODS' | 物料类型：RAW_MATERIAL / FINISHED_GOODS（新增） |
| status | VARCHAR | 20 | 'ACTIVE' | 状态：ACTIVE / INACTIVE（IMS原有字段，保留） |

**唯一约束**：`sku_code` 设为唯一键（UNIQUE），确保一个编码只对应一个物料。

**数据示例：**

| 2 | 202-018 | 115采集模块 | HD-AU902 | 套 | FINISHED_GOODS |

### 2.2 物料编码在 Excel 中的展示方式

**导出时（如出货台账 Excel）：**

| 序号 | **名称** | 规格 | 产品编号 | 数量 |
|------|----------|------|---------|------|
| 1 | `202-046` | `HD-AU906A` | `HD001482605001` | 1 |
| | `148采集单元` | | | |

在 Excel 中“名称”列导出**两行**：
- 第一行：`sku_code`（物料编码）
- 第二行：`sku_name`（物料名称）
- 用 Excel 单元格换行（Alt+Enter）实现

**在系统页面列表中：** 显示为 `202-046 / 148采集单元` 或分为两列（物料编码 + 物料名称）。

**导入时：**
1. 用户上传 Excel
2. 系统读取“名称”列的内容：
   - 如果包含换行 → 拆出物料编码和物料名称
   - 如果是单行 → 尝试作为物料编码匹配
3. 用 `sku_code` 在 `product_sku` 表中查找匹配
4. 匹配到 → 存入 `sku_id`，同时冗余字段记录当前值
5. 匹配不到 → 报错“未找到物料编码 XXX”

## 第四章：物料编码与物料名称的业务规则

### 4.1 录入规则

所有业务表（出货单、退货单、到货单等）录入时：

1. **用户操作**：在物料选择器中输入 `sku_code`（物料编码）或 `sku_name`（物料名称）搜索
2. **系统匹配**：从 `product_sku` 表中匹配对应的物料
3. **自动填充**：选择后，系统自动将 `sku_id`、`sku_code`、`sku_name`、`spec`、`unit` 写入业务表

> ⚠️ **unit 兜底逻辑**：`product_sku.unit` 允许为空，但业务表的 `unit` 字段为 NOT NULL。后端在自动填充时，若 `product_sku.unit` 为 NULL 或空字符串，则默认赋值为 `'个'`，避免数据库插入报错。同时，物料维护界面应强制要求填写 `unit`（前端设为必填）。

### 4.2 Excel 导出规则

所有业务表的 Excel 导出，**“名称”列按以下格式**：

- 第一行：`sku_code`（物料编码）
- 第二行：`sku_name`（物料名称）
- 用 Excel 单元格换行（Alt+Enter）实现

示例：

| 名称 | 规格 | 产品编号 |
|------|------|---------|
| `202-046` | `HD-AU906A` | `HD001482605001` |
| `148采集单元` | | |

### 4.3 Excel 导入规则

所有业务表的 Excel 导入，**以 `sku_code`（物料编码）为唯一匹配键**，规格型号仅作展示和辅助验证，不用于主匹配逻辑。

导入解析逻辑：

1. 读取"名称"列的内容：
   - 如果包含换行符 → 拆分为两行，第一行作为 `sku_code`，第二行作为 `sku_name`
   - 如果是单行 → 进入多级匹配流程
2. **多级匹配**（兼容业务员手滑只填名称的情况）：
   - **第一级**：尝试作为 `sku_code` 在 `product_sku` 表中精确匹配
   - **第二级**：若匹配失败，尝试作为 `sku_name` 在 `product_sku` 表中精确匹配
   - **第三级**：若仍失败，报错并列出"疑似物料"（模糊匹配 `sku_name` LIKE `%输入值%` 的前 5 条结果），供人工选择
   - 匹配到 → 自动用 `product_sku` 表中的 `name`、`spec`、`unit` 覆盖 Excel 中的对应值（**以系统为准**），写入 `sku_id` + 冗余字段
   - 匹配不到且无模糊结果 → 报错"未找到物料编码或名称 XXX"，阻断导入
3. 如果 Excel 中"名称"列为空 → 报错"请填写物料编码或物料名称"，因为规格型号可能对应多个编码，无法唯一确定

```python
for row_idx, row_data in enumerate(data_rows, start=2):
    fill = PatternFill(start_color=ROW_BG_ODD if row_idx % 2 == 0 else ROW_BG_EVEN,
                       end_color=ROW_BG_ODD if row_idx % 2 == 0 else ROW_BG_EVEN,

    for col_idx, value in enumerate(row_data, start=1):
        cell = ws.cell(row=row_idx, column=col_idx, value=value)
```

## 第七章：核心业务逻辑说明

### 7.1 新旧SN关联机制

维修完成后：
1. 测试工程师手动输入新 SN（支持扫码）
2. 系统校验新 SN 是否已存在（重复则拦截）
3. 系统自动建立关联：
   - 旧 SN 的 `replaced_by_sn` = 新 SN
   - 旧 SN 的 `stock_status` = `REPLACED`
   - 新 SN 的 `replaced_from_sn` = 旧 SN
   - 新 SN 的 `stock_status` = `IN_STOCK`
   - 新 SN 的 `current_location` = '库房'
4. 审计日志记录完整变更链路

### 7.2 报废审批流程

```
质量负责人发起报废申请
  ↓
状态：待审批
  ↓
总经理 或 仓库管理员（任意一人）
  ├→ 通过 → 状态：已报废
  └→ 驳回 → 状态：回退到待维修
```

### 7.3 维修用料扣库存流程


### 7.4 原材料库存管理（批次 + 可选SN双轨制）

**无 SN 批次**：
- 只在 `raw_material_inventory` 记录数量
- 扣减时按数量扣减

**有 SN 批次**：
- `raw_material_inventory` 记录总数量
- `raw_material_sn` 逐条记录每个 SN
- 扣减时按 SN 逐件扣减，同时扣减批次总数量

### 7.5 原材料SN状态枚举

```python
class RawMaterialSNStatus(str, enum.Enum):
    IN_STOCK = "IN_STOCK"      # 在库
    CONSUMED = "CONSUMED"      # 已消耗（用于生产）
    DEFECTIVE = "DEFECTIVE"    # 不良品（来料检验发现）
    RETURNED = "RETURNED"      # 已退货
    SCRAPPED = "SCRAPPED"      # 已报废（生产过程报废）
```

**状态流转：**
```
来料检验合格 → IN_STOCK → CONSUMED（生产领用）或 SCRAPPED（生产过程报废）
来料检验不合格 → DEFECTIVE → RETURNED（退货给供应商）
```

### 7.6 `rma_return.current_handler` 字段生命周期

| 阶段 | current_handler 值 | 说明 |
|------|-------------------|------|
| 创建退货单 | NULL | 尚未分配处理人 |
| 质量负责人分配任务 | 被分配人（测试工程师或生产人员） | 写入被分配人用户名 |
| 流转设备 | 下一处理人 | 更新为新的处理人 |
| 维修完成 | 保持不变（最后处理人） | 不修改 |
| 已报废/已再出货 | 保留为最后处理人 | 历史记录保留，不修改 |

### 7.7 `incoming_inspection.change_reason` 前端交互要求

当用户修改检验结论（`result`）时，前端必须执行以下交互：

1. **UI 高亮提示**：`change_reason` 输入框边框变红，placeholder 显示"检验结论已变更，请填写变更原因（选填但强烈建议）"
2. **不强制阻断**：`change_reason` 仍为选填字段，校验结论变更时不强制要求填写，避免卡流程
3. **审计日志关联**：无论 `change_reason` 是否填写，审计日志均记录 `before_value`（旧结论）和 `after_value`（新结论），`change_reason` 有值则一并记录

> **设计理由**：`change_reason` 选填是为了不阻断紧急操作流程，但 UI 高亮提醒能大幅提升后续追溯效率。当检验结论从"不合格"改为"合格"（特批放行）时，强制高亮尤为重要。

## 第九章：数据迁移说明

### 9.1 现有 SKU 的 `sku_type` 与 `sku_code` 迁移

新增字段时设置 `default='FINISHED_GOODS'`，现有数据自动填充 `sku_type`。

`sku_code` 字段新增后为 NULL，需手动填充。步骤：

```sql
-- 1. 先新增 sku_code 字段（允许 NULL）
ALTER TABLE product_sku ADD COLUMN sku_code VARCHAR(50) UNIQUE;

-- 2. 根据现有 name 字段填充 sku_code（示例数据，实际需从 U9 系统导出）
UPDATE product_sku SET sku_code = '202-046' WHERE name = '148采集单元';
UPDATE product_sku SET sku_code = '202-018' WHERE name = '115采集模块';
UPDATE product_sku SET sku_code = '306-058' WHERE name = '工控机';
-- ... 按实际数据逐一填充

-- 3. 填充完成后，改为 NOT NULL
ALTER TABLE product_sku MODIFY sku_code VARCHAR(50) NOT NULL;
```

> 注意：`sku_code` 的填充数据需要从 U9 系统导出，建议在数据迁移阶段由 DBA 或管理员执行。

### 9.2 现有 SN 的 `current_location` 自动填充

```sql
UPDATE inventory_item 
SET current_location = CASE 
    WHEN stock_status = 'IN_STOCK' THEN '库房'
    WHEN stock_status IN ('SOLD', 'SOLD_OFFLINE', 'BORROWED', 'GIFTED', 'RND', 'SAMPLE', 'TRIAL', 'PRESOLD', 'DEPT_PROCUREMENT') THEN '已发出'
    WHEN stock_status = 'SCRAPPED' THEN '已报废'
    WHEN stock_status = 'REPAIR' THEN '维修中'
    ELSE '库房'
END
WHERE current_location IS NULL;
```
