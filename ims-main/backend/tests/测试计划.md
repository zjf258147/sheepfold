# IMS 测试计划

## 一、测试体系概览

IMS 测试体系包含三大类测试，覆盖四条业务主线（A/B/C/D）的全部功能：

| 类型 | 测试目标 | 运行命令 | 标记 |
|------|----------|----------|------|
| 合约测试 | 验证 API 接口的请求/响应格式、状态码、字段完整性 | `uv run pytest tests/contract/ -m contract` | `contract` |
| 场景测试 | 验证端到端业务流程完整性 | `uv run pytest tests/scenario/ -m scenario` | `scenario` |
| 快照测试 | 验证 UI 组件渲染结构（待实现） | `npm run test:snapshot` | `snapshot` |

## 二、测试目录结构

```
ims-main/backend/tests/
├── __init__.py
├── conftest.py                  # 共享 fixture：数据库隔离、客户端、Token

├── debug_response.py            # 调试脚本（查看 API 响应格式）

│   ├── test_shipment_contract.py   # 主线C：出货管理合约测试（7条）
│   └── test_bom_contract.py        # 主线D：BOM管理合约测试（9条）
└── scenario/                    # 场景测试

```

## 四、测试运行命令

### 4.1 全部测试

```bash
# 运行全部测试
cd ims-main/backend
uv run pytest tests/ -v

# 运行全部测试（含覆盖率）
uv run pytest tests/ -v --cov=app --cov-report=term --cov-report=html
```

### 4.2 按类型运行

```bash
# 合约测试（验证 API 接口格式）
uv run pytest tests/contract/ -v -m contract

# 场景测试（验证端到端业务流程）
uv run pytest tests/scenario/ -v -m scenario

# 烟雾测试（快速基础验证）
uv run pytest tests/ -v -m smoke
```

### 4.3 按主线运行

```bash
# 主线A：来料管理
uv run pytest tests/contract/test_incoming_contract.py tests/scenario/test_scenario_mainline_a.py -v

# 主线B：返厂维修
uv run pytest tests/contract/test_rma_contract.py tests/scenario/test_scenario_mainline_b.py -v

# 主线C：出货管理
uv run pytest tests/contract/test_shipment_contract.py tests/scenario/test_scenario_mainline_c.py -v

# 主线D：BOM管理
uv run pytest tests/contract/test_bom_contract.py tests/scenario/test_scenario_mainline_d.py -v

# 文档下载 & APK
uv run pytest tests/contract/test_docs_contract.py tests/scenario/test_docs_scenario.py -v

# 二期功能（场站/设备台账/盘点/库存调整/文档下载）
uv run pytest tests/contract/ -v -k "docs or station or stocktake or adjustment or device"
```

### 4.4 单个测试用例

```bash
# 运行指定测试类
uv run pytest tests/contract/test_incoming_contract.py::TestIncomingReceiptContract -v

# 运行指定测试方法
uv run pytest tests/scenario/test_scenario_mainline_a.py::TestScenarioS001::test_full_incoming_flow -v

# 运行匹配关键字的测试
uv run pytest tests/ -v -k "scrap"
```

### 6.2 测试数据

| 数据 | 编码 | 类型 | 用途 |
|------|------|------|------|
| 测试原材料 | `202-018` | 原材料 | 主线A/C/D 测试 |

| 测试供应商 | — | 供应商 | 主线A 测试 |

### 6.3 数据库隔离

- 使用 SQLite `:memory:` 内存数据库
- 每个测试用例独立数据库会话，测试结束后自动回滚
- `BigInteger` 主键自动转换为 `Integer`（兼容 SQLite）

## 八、测试编写规范

### 8.1 命名规范

```
文件名：test_{模块名}_contract.py / test_scenario_mainline_{x}.py
类名：  Test{模块名}Contract / TestScenarioS{编号}
方法名：test_{动作}_{场景}_{预期结果}
```

### 8.2 测试标记

```python
@pytest.mark.contract
def test_create_receipt_success_returns_201(self, client, auth_headers, seed_data):
    ...

@pytest.mark.scenario
def test_full_incoming_flow(self, client, auth_headers, seed_data):
    ...
```

### 8.3 响应格式说明

| 端点类型 | 响应格式 | 数据访问方式 |
|----------|----------|-------------|
| Incoming POST/PUT/GET | 原始数据 | `res.json()["status"]` |
| RMA POST | 原始数据 | `res.json()["return_no"]` |
| RMA GET | R 包装 | `res.json()["data"]["status"]` |
| Shipment POST/GET | R 包装 | `res.json()["data"]["shipment_no"]` |
| BOM POST/GET | R 包装 | `res.json()["data"]["bom_no"]` |
| 失败响应 | R.fail (HTTP 200, code=-1) | `res.json()["code"] != 0` |

## 九、已知注意事项

1. **测试隔离**：每个测试用例使用独立的数据库会话，但 `seed_data` fixture 的数据在测试间共享（commit 后不回滚）
2. **SQLite 兼容**：`BigInteger` 主键在 SQLite 中不支持自增，`conftest.py` 中自动转换为 `Integer`
3. **业务逻辑**：`rma_service.py` 中诊断结果为 SCRAP 时不再立即设置状态为 SCRAPPED，改为在报废审批通过后设置
4. **调试脚本**：`tests/debug_response.py` 可直接运行，用于查看 API 实际响应格式
