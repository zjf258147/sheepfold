## 0.1 本文档的定位

《二次开发说明书》是 IMS 系统三份核心文档之一，定位如下：

| 维度 | 《系统说明书》 | 《用户操作手册》 | 《二次开发说明书》 |
|------|:---:|:---:|:---:|
| **受众** | 管理员/IT/业务负责人 | 一线操作人员 | **开发人员/二期接手者** |
| **核心问题** | 系统是什么、怎么运作 | 我怎么操作 | **我怎么改、怎么扩展** |
| **视角** | 业务视角 | 操作视角 | **技术视角** |
| **是否含代码** | ❌ | ❌ | **✅** |
| **更新频率** | 低 | 中 | **高（随代码变）** |

**本文档解决的核心问题**：

- 接手二期开发时，如何从零搭建开发环境
- 代码目录结构是怎样的，每个文件做什么
- 新增功能时，后端的 Model / Schema / Service / API 怎么写
- 新增页面时，前端的 Vue 组件 / Store / 路由怎么配
- 如何执行数据库迁移、运行测试、部署上线
- 已知的技术坑有哪些，如何避免

**本文档不包含的内容**（请查阅对应文档）：

| 内容 | 查阅文档 |
|------|---------|
| 业务背景、业务流程、业务规则 | 《系统说明书》 |
| 如何操作系统界面 | 《用户操作手册》 |
| 部署后的运维管理 | 《系统说明书》第10章 |

## 0.4 文档更新流程

本文档随代码变更同步更新，流程如下：

1. **代码变更** → 检查是否影响本文档描述的内容（新增API、新增字段、新增模块等）
2. **更新文档** → 修改对应章节
3. **更新版本记录** → 在文档首页版本号递增
4. **运行数据字典脚本** → 重新生成附录A（如有表结构变更）

```bash
$ cd backend
$ python scripts/generate_data_dict.py
```

5. **提交** → 使用 `docs:` 前缀提交

```
docs: 更新二次开发说明书第3章新增API模板
```

> 本文档版本号跟随系统版本号。系统发布新版本时，本文档同步更新至对应版本。

## 0.5 文档约定

### 格式说明

本文档遵循《文档编写规范》第七章"二次开发说明书专属规范"，关键约定如下：

| 约定 | 说明 | 示例 |
|------|------|------|
| 代码片段 | ≤30行贴完整代码，>30行贴关键行+文件路径 | 见第3章各节 |
| 文件路径 | 项目内相对路径 | `backend/app/models/enums.py` |
| API 格式 | 七行属性表格 + JSON 示例 | 见第3.3节 |
| 表结构 | 五列表格（字段名、类型、必填、默认值、说明） | 见第5章 |
| 命令行 | `$` 前缀，cd 独立一行 | `$ cd backend` |
| 引用系统说明书 | 引用块 + 章节号 | `> 详见《系统说明书》第4.1节` |

### 符号说明

| 符号 | 含义 |
|:---:|------|
| ⚠️ | 重要注意事项，忽略可能导致 bug |
| 💡 | 技巧或最佳实践建议 |
| ❌ | 禁止操作或易错点 |
| 🛠️ | 工具或命令 |
