## 1.2 后端环境搭建（本地开发）

### 1.2.1 创建环境配置

```bash
$ cd backend
$ cp .env.example .env
```

编辑 `.env` 文件，至少修改以下三项：

| 变量 | 说明 | 示例 |
|------|------|------|
| `MYSQL_HOST` | 数据库主机 | `localhost` |
| `MYSQL_PASSWORD` | 数据库密码 | `your_password` |
| `JWT_SECRET_KEY` | JWT 签名密钥 | 随机长字符串（如 `openssl rand -hex 32`） |

> ⚠️ `JWT_SECRET_KEY` 生产环境必须修改为随机长字符串，否则 Token 可被伪造。

### 1.2.2 安装依赖

```bash
$ uv sync
```

`uv` 自动读取 `pyproject.toml` 安装所有依赖，包含：

| 依赖 | 用途 |
|------|------|
| `fastapi` + `uvicorn` | Web 框架与 ASGI 服务器 |
| `sqlalchemy` + `alembic` + `pymysql` | ORM、数据库迁移、MySQL 驱动 |
| `python-jose` + `bcrypt` | JWT 鉴权 |
| `pydantic-settings` | 配置管理 |
| `redis` + `apscheduler` | 缓存与定时任务 |
| `openpyxl` + `xlrd` | Excel 导入导出 |
| `loguru` | 日志 |

### 1.2.3 初始化数据库

确保 MySQL 已启动，且 `.env` 中的连接信息正确。

```bash
# 执行数据库迁移（创建所有表）
$ uv run alembic upgrade head

# 创建管理员账号（已存在则跳过）
$ uv run python scripts/init_admin.py
```

### 1.2.4 启动开发服务器

```bash
$ uv run uvicorn main:app --reload --host 0.0.0.0 --port 8000
```

| 参数 | 说明 |
|------|------|
| `--reload` | 代码变更自动重启（开发模式） |
| `--host 0.0.0.0` | 监听所有网络接口 |
| `--port 8000` | 服务端口 |

启动后访问：

| 地址 | 内容 |
|------|------|
| http://localhost:8000/health | 健康检查 |
| http://localhost:8000/docs | Swagger 文档（需 `DEBUG=true`） |

### 1.2.5 验证安装

```bash
$ curl http://localhost:8000/health
{"status": "ok"}
```

## 1.3 前端环境搭建（本地开发）

### 1.3.1 创建环境配置

```bash
$ cd frontend
$ cp .env.example .env
```

编辑 `.env` 文件，设置后端 API 地址：

```
VITE_API_TARGET=http://localhost:8000
```

### 1.3.2 安装依赖

```bash
$ npm install
```

主要依赖：

| 依赖 | 用途 |
|------|------|
| `vue` + `vue-router` | 前端框架与路由 |
| `element-plus` + `@element-plus/icons-vue` | UI 组件库 |
| `pinia` | 状态管理 |
| `axios` | HTTP 客户端 |
| `mermaid` | 流程图渲染 |
| `jsbarcode` + `html5-qrcode` | 条码/二维码 |

### 1.3.3 启动开发服务器

```bash
$ npm run dev
```

默认启动 `http://localhost:5173`（Vite 默认端口）。

### 1.3.4 验证安装

浏览器打开 `http://localhost:5173`，应看到登录页面。使用 `admin` / `admin123` 登录。

## 1.4 Docker 一键启动

> 生产环境或不想手动配置本地依赖时使用。

### 1.4.1 环境要求

| 组件 | 版本 |
|------|------|
| Docker | 20.10+ |
| Docker Compose | v2+ |

### 1.4.2 启动步骤

```bash
# 1. 克隆项目
$ git clone https://gitee.com/java0904_cloud/ims-opensource.git
$ cd ims-opensource

# 2. 配置环境变量（至少修改三处密钥）
$ cp .env.example .env

# 3. 一键构建并启动
$ docker compose up -d --build
```

### 1.4.3 容器架构

`docker-compose.yml` 定义四个服务：

| 服务 | 镜像 | 端口 | 说明 |
|------|------|------|------|
| `mysql` | `mysql:5.7` | `3306` | 数据库，utf8mb4 编码 |
| `redis` | `redis:7-alpine` | `6379` | 缓存（最大 256MB，LRU 淘汰） |
| `backend` | 构建自 `./backend` | `8000` | FastAPI 后端，依赖 mysql + redis |
| `frontend` | 构建自 `./frontend` | `8080` | Vue 3 前端，Nginx 提供静态资源 |

### 1.4.4 常用命令

```bash
# 查看运行状态
$ docker compose ps

# 查看后端日志
$ docker compose logs -f backend

# 停止服务
$ docker compose down

# 停止并清除数据卷（会删除数据库数据！）
$ docker compose down -v
```

## 1.5 常见环境问题排查

### 1.5.1 后端

| 问题 | 可能原因 | 解决方法 |
|------|---------|---------|
| `ModuleNotFoundError` | 未安装依赖 | `uv sync` |
| `Can't connect to MySQL` | MySQL 未启动或连接信息错误 | 检查 `.env` 中的 `MYSQL_HOST`、`MYSQL_PORT` |
| `Access denied for user` | 用户名或密码错误 | 检查 `MYSQL_USER`、`MYSQL_PASSWORD` |
| `Unknown database` | 数据库未创建 | 手动创建：`CREATE DATABASE ims DEFAULT CHARSET utf8mb4` |
| `alembic` 报错 | 迁移版本不一致 | `uv run alembic stamp head` 再 `uv run alembic upgrade head` |
| 端口被占用 | 8000 端口已使用 | `--port 8001` 更换端口 |
| Swagger 无法访问 | `DEBUG=false` | 开发时将 `.env` 中 `DEBUG` 设为 `true` |

### 1.5.2 前端

| 问题 | 可能原因 | 解决方法 |
|------|---------|---------|
| `npm install` 报错 | Node 版本过低 | 升级到 Node 20+ |
| `npm install` 慢 | 国内网络 | 设置镜像：`npm config set registry https://registry.npmmirror.com` |
| 页面空白 | 后端未启动 | 先启动后端 `uv run uvicorn main:app --reload` |
| 登录后报 401 | JWT 密钥不一致 | 检查前后端 `.env` 中的 `JWT_SECRET_KEY` |
| 跨域错误 | CORS 配置问题 | 检查后端 `.env` 中 `CORS_ORIGINS` 是否包含前端地址 |
| API 请求 404 | 代理配置错误 | 检查 `frontend/.env` 中 `VITE_API_TARGET` 指向正确的后端地址 |

### 1.5.3 Docker

| 问题 | 可能原因 | 解决方法 |
|------|---------|---------|
| 容器启动失败 | 端口被占用 | 修改 `.env` 中的 `FRONTEND_PORT`、`BACKEND_PORT`、`MYSQL_PORT` |
| 数据库连接失败 | MySQL 未就绪 | 等待 MySQL 健康检查通过（最多 30 次 × 5 秒） |
| 构建缓慢 | Docker 缓存未命中 | 首次构建较慢是正常的，后续使用缓存 |
| macOS 端口占用 | AirPlay 占用 8000 | 修改 `BACKEND_PORT` |

### 1.5.4 通用排查步骤

当启动后无法正常使用，按以下顺序排查：

1. 检查 MySQL 服务是否运行：`mysqladmin ping -h localhost`
2. 检查后端健康状态：`curl http://localhost:8000/health`
3. 检查前端是否可访问：浏览器打开 `http://localhost:5173`
4. 检查 `.env` 配置是否正确
5. 查看后端日志：终端输出 或 Docker 日志
