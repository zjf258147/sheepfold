## 3.1 分层架构

后端采用四层架构，严格遵循**单向依赖**：`api → service → models`

```
api/         ← HTTP 端点，参数校验，权限检查，调用 service
  │
  ▼
service/     ← 业务逻辑，事务管理，数据组装
  │
  ▼
models/      ← ORM 声明，表结构定义
```

**约束规则**：

| 规则 | 说明 |
|------|------|
| ❌ api 直接操作数据库 | api 不应直接 `db.query()` 或 `db.add()` |
| ❌ api 包含复杂逻辑 | api 负责校验和组装响应，复杂逻辑必须在 service |
| ❌ service 返回 HTTP 异常 | service 抛出 Python 异常，api 捕获后转 HTTP 异常 |
| ✅ models 可被所有层引用 | models 是数据基础层 |
| 🔐 权限控制 | 使用 `require_roles` 装饰器，详见 3.5.3 |

## 3.2 模型层规范（Models）

### 3.2.1 基类继承

所有业务模型必须同时继承 `Base` 和 `TimestampMixin`：

```python
from app.db.base import Base, TimestampMixin

class InboundOrder(Base, TimestampMixin):
    __tablename__ = "inbound_order"
    # 字段定义...
```

> `Base` 提供 ORM 能力，`TimestampMixin` 自动添加 `created_at` / `updated_at` 字段。不要手动定义这两个字段。

### 3.2.2 字段定义

使用 SQLAlchemy 2.0 的 `Mapped` 类型注解语法：

```python
from sqlalchemy import BigInteger, DateTime, ForeignKey, Integer, String, Numeric, func
from sqlalchemy.orm import Mapped, mapped_column, relationship

class MyModel(Base, TimestampMixin):
    __tablename__ = "my_table"

    id: Mapped[int] = mapped_column(BigInteger, primary_key=True, autoincrement=True)
    name: Mapped[str] = mapped_column(String(100), nullable=False, comment="名称")
    status: Mapped[str] = mapped_column(String(30), default="active", index=True)
    parent_id: Mapped[int | None] = mapped_column(Integer, ForeignKey("parent.id"), nullable=True)
```

**字段定义规则**：

| 规则 | 正确示例 | 错误示例 |
|------|---------|---------|
| 主键用 `BigInteger` + 自增 | `mapped_column(BigInteger, primary_key=True, autoincrement=True)` | `mapped_column(Integer, ...)` |
| 必填字段加 `nullable=False` | `mapped_column(String(100), nullable=False)` | 省略 |
| 可选字段类型写 `\| None` | `Mapped[str \| None]` | `Mapped[str]` |
| 外键必须写 `ForeignKey` | `ForeignKey("partner.id")` | 手动管理关联 |
| 枚举字段用 `index=True` | `mapped_column(String(30), index=True)` | 无索引 |
| 金额用 `Numeric(12, 2)` | `Numeric(12, 2)` | `Float` 或 `Integer` |
| **必须写 `comment`** | `comment="入库单号"` | 省略（数据字典依赖此值） |

### 3.2.3 关联关系

```python
# 一对多：主表 has many 子表
lines: Mapped[list["InboundOrderLine"]] = relationship(
    back_populates="order", cascade="all, delete-orphan"
)

# 多对一：子表 belongs to 主表
order: Mapped["InboundOrder"] = relationship(back_populates="lines")

# 引用非主键关联（延迟加载）
partner: Mapped["Partner"] = relationship(foreign_keys=[partner_id], lazy="select")
```

> ⚠️ 关联关系默认使用 `lazy="select"`（单条查询时自动 JOIN），避免 N+1 查询问题。

### 3.2.4 属性计算

需要在模型中定义计算属性时，使用 `@property`：

```python
@property
def partner_name(self) -> str | None:
    return self.partner.name if self.partner else None
```

> 💡 计算属性用于给 ORM 对象添加便捷的只读属性，例如关联表的名称。

### 3.2.5 枚举定义

项目枚举统一在 [models/enums.py](file:///c:/Users/25075/Desktop/IMS生产物料与产品追溯管理系统/ims-main/backend/app/models/enums.py) 中定义：

```python
import enum

class OperationStatus(str, enum.Enum):
    INITIATED = "INITIATED"
    PENDING_REVIEW = "PENDING_REVIEW"
    APPROVED = "APPROVED"
    REJECTED = "REJECTED"

class InboundMode(str, enum.Enum):
    PROCUREMENT = "PROCUREMENT"
    NON_PROCUREMENT = "NON_PROCUREMENT"
```

**新增枚举规则**：
1. 枚举类放在 `enums.py`，不要散落在各模型文件
2. 使用 `str, enum.Enum` 双重继承，保证 JSON 序列化兼容
3. 枚举值全大写，用下划线分隔
4. 字典/映射常量（如 `STATUS_TO_TEXT`）也放在 `enums.py`

## 3.3 Schema 层规范（Pydantic）

### 3.3.1 统一响应：`R[T]`

所有 API 响应必须使用 `R[T]` 包装：

```python
from app.schemas.common import R

# 成功
return R.ok(data=my_data)
return R.ok(data=my_data, msg="操作成功")

# 失败（业务错误，HTTP 200）
return R.fail(msg="SN 已存在", code=4001)
```

> `R.fail()` 返回的 HTTP 状态码仍然是 200，通过 `code` 字段区分业务错误。只有认证/权限异常才使用 `HTTPException` 抛 401/403。

### 3.3.2 分页响应：`PageResult[T]`

```python
from app.schemas.common import PageResult

return R.ok(data=PageResult(
    total=total_count,
    page=page,
    page_size=page_size,
    items=[ItemResponse.model_validate(item) for item in db_items],
))
```

### 3.3.3 Schema 命名规范

| 后缀 | 用途 | 示例 |
|------|------|------|
| `Create` | 创建请求体 | `InboundOrderCreate` |
| `Update` | 更新请求体 | `InboundOrderUpdate` |
| `Response` | 响应体（完整） | `InboundOrderResponse` |
| `ListItem` | 列表项（精简） | `ProductListItem` |
| `Line` | 子行数据 | `InboundLineCreate` |

### 3.3.4 Schema 定义示例

```python
from pydantic import BaseModel, Field
from datetime import datetime
from decimal import Decimal

class InboundOrderCreate(BaseModel):
    """入库单创建请求。"""
    inbound_mode: str = Field(min_length=1, description="入库模式")
    stock_condition: str = Field(min_length=1, description="库存属性")
    partner_id: int = Field(gt=0, description="往来单位ID")
    remark: str | None = Field(None, max_length=500)
    lines: list[InboundLineCreate] = Field(min_length=1, description="入库商品行")


class InboundOrderResponse(BaseModel):
    """入库单响应。"""
    id: int
    order_no: str
    inbound_mode: str
    stock_condition: str
    total_qty: int
    operation_status: str
    partner_name: str | None = None
    created_at: datetime
    updated_at: datetime

    model_config = {"from_attributes": True}
```

> ⚠️ 响应 Schema 必须设置 `model_config = {"from_attributes": True}`，以便从 ORM 对象直接转换。

### 3.3.5 字段验证

使用 Pydantic `Field` 进行字段级校验：

```python
name: str = Field(min_length=1, max_length=100, description="名称")
email: str | None = Field(None, pattern=r"^[\w\.-]+@[\w\.-]+\.\w+$")
quantity: int = Field(gt=0, le=999999, description="数量")
```

> `description` 字段也会出现在 Swagger 文档中，需要认真填写。

## 3.4 服务层规范（Service）

### 3.4.1 函数命名

| 操作 | 命名 | 示例 |
|------|------|------|
| 列表查询 | `get_xxx` | `get_orders(db, page, ...)` |
| 单条查询 | `get_xxx_by_id` | `get_order_by_id(db, order_id)` |
| 创建 | `create_xxx` | `create_order(db, data, user)` |
| 更新 | `update_xxx` | `update_order(db, order_id, data)` |
| 审核 | `review_xxx` | `review_order(db, order_id, action, user)` |
| Excel 导出 | `export_xxx` | `export_orders(db, filters)` |

### 3.4.2 参数约定

```python
def get_orders(
    db: Session,                # ← 第一个参数：数据库 Session
    page: int = 1,              # ← 分页参数
    page_size: int = 20,
    operation_status: str | None = None,  # ← 筛选参数（可选）
    inbound_mode: str | None = None,
) -> tuple[int, list[InboundOrder]]:     # ← 返回 (总数, 数据列表)
```

> ⚠️ 所有 service 函数第一个参数必须是 `db: Session`，由调用方（api 层）通过 `Depends(get_db)` 注入。

### 3.4.3 查询构建

```python
query = db.query(InboundOrder).options(
    joinedload(InboundOrder.partner).joinedload(Partner.group)
)

# 条件筛选——每个条件独立判断
if operation_status:
    query = query.filter(InboundOrder.operation_status == operation_status)

if order_no:
    query = query.filter(InboundOrder.order_no.like(f"%{order_no}%"))

# 分页
total = query.count()
items = query.order_by(InboundOrder.id.desc()).offset((page - 1) * page_size).limit(page_size).all()
```

> 💡 使用 `joinedload` 预加载关联对象，避免在循环中触发 N+1 查询。

### 3.4.4 事务处理

SQLAlchemy Session 自带事务。简单操作无需手动管理，复杂操作使用 `db.flush()` 获取 ID：

```python
order = InboundOrder(...)
db.add(order)
db.flush()  # 立即写入获取 order.id，但事务未提交

# 使用 order.id 创建子记录
for line in data.lines:
    db.add(InboundOrderItem(inbound_order_id=order.id, ...))

# api 层返回后，FastAPI 自动调用 db.commit()
```

> ⚠️ 不要在 service 中调用 `db.commit()`——由 FastAPI 在请求结束时自动提交。如果业务需要回滚，抛出异常即可。

### 3.4.5 错误处理

Service 层抛出 Python 标准异常，由 api 层捕获并转换为 HTTP 异常：

```python
# service 层
def create_order(db: Session, data: InboundOrderCreate, user: User):
    partner = db.get(Partner, data.partner_id)
    if not partner:
        raise ValueError("往来单位不存在")
    # ...

# api 层
try:
    order = inbound_service.create_order(db, data, user)
except ValueError as e:
    raise HTTPException(status_code=400, detail=str(e))
```

## 3.8 新增功能完整示例

以"新增一个 FAQ 管理模块"为例，展示完整开发流程。

### Step 1: 定义模型 `models/faq.py`

```python
from sqlalchemy import BigInteger, Integer, String, Text
from sqlalchemy.orm import Mapped, mapped_column

from app.db.base import Base, TimestampMixin


class Faq(Base, TimestampMixin):
    __tablename__ = "faq"

    id: Mapped[int] = mapped_column(BigInteger, primary_key=True, autoincrement=True)
    question: Mapped[str] = mapped_column(String(500), nullable=False, comment="问题")
    answer: Mapped[str] = mapped_column(Text, nullable=False, comment="答案")
    sort_order: Mapped[int] = mapped_column(Integer, default=0, comment="排序")
    status: Mapped[str] = mapped_column(String(20), default="PUBLISHED", comment="状态")
```

### Step 2: 生成数据库迁移

```bash

$ uv run alembic revision --autogenerate -m "add faq table"
$ uv run alembic upgrade head
```

### Step 3: 定义 Schema `schemas/faq.py`

```python
from pydantic import BaseModel, Field
from datetime import datetime


class FaqCreate(BaseModel):
    question: str = Field(min_length=1, max_length=500)
    answer: str = Field(min_length=1)
    sort_order: int = Field(0, ge=0)
    status: str = Field("PUBLISHED")


class FaqUpdate(BaseModel):
    question: str | None = None
    answer: str | None = None
    sort_order: int | None = None
    status: str | None = None


class FaqResponse(BaseModel):
    id: int
    question: str
    answer: str
    sort_order: int
    status: str
    created_at: datetime
    updated_at: datetime

    model_config = {"from_attributes": True}
```

### Step 4: 编写 Service `service/faq_service.py`

```python
from sqlalchemy.orm import Session
from app.models.faq import Faq
from app.schemas.faq import FaqCreate, FaqUpdate


def list_faq(db: Session, page: int = 1, page_size: int = 20):
    query = db.query(Faq)
    total = query.count()
    items = query.order_by(Faq.sort_order.asc(), Faq.id.desc()) \
                 .offset((page - 1) * page_size).limit(page_size).all()
    return total, items


def create_faq(db: Session, data: FaqCreate) -> Faq:
    faq = Faq(**data.model_dump())
    db.add(faq)
    db.flush()
    return faq


def update_faq(db: Session, faq_id: int, data: FaqUpdate) -> Faq:
    faq = db.query(Faq).filter(Faq.id == faq_id).first()
    if not faq:
        raise ValueError("FAQ 不存在")
    update_data = data.model_dump(exclude_unset=True)
    for key, value in update_data.items():
        setattr(faq, key, value)
    db.flush()
    return faq


def delete_faq(db: Session, faq_id: int):
    faq = db.query(Faq).filter(Faq.id == faq_id).first()
    if not faq:
        raise ValueError("FAQ 不存在")
    db.delete(faq)
    db.flush()
```

### Step 5: 定义 API `api/faq.py`

```python
from fastapi import APIRouter, Depends, HTTPException
from sqlalchemy.orm import Session
from app.core.deps import get_current_user, require_roles
from app.db.database import get_db
from app.models.user import User
from app.schemas.common import R, PageResult
from app.schemas.faq import FaqCreate, FaqUpdate, FaqResponse
from app.service import faq_service

router = APIRouter(prefix="/faq", tags=["FAQ"])


@router.get("", response_model=R[PageResult[FaqResponse]], summary="FAQ列表")
def list_faq(
    page: int = 1,
    page_size: int = 20,
    db: Session = Depends(get_db),
    _: User = Depends(get_current_user),
):
    total, items = faq_service.list_faq(db, page, page_size)
    return R.ok(data=PageResult(
        total=total, page=page, page_size=page_size,
        items=[FaqResponse.model_validate(i) for i in items],
    ))


@router.post("", response_model=R[FaqResponse], summary="新增FAQ")
def create_faq(
    data: FaqCreate,
    db: Session = Depends(get_db),
    user: User = Depends(require_roles("ADMIN")),
):
    faq = faq_service.create_faq(db, data)
    return R.ok(data=FaqResponse.model_validate(faq), msg="新增成功")


@router.put("/{faq_id}", response_model=R[FaqResponse], summary="更新FAQ")
def update_faq(
    faq_id: int,
    data: FaqUpdate,
    db: Session = Depends(get_db),
    user: User = Depends(require_roles("ADMIN")),
):
    try:
        faq = faq_service.update_faq(db, faq_id, data)
        return R.ok(data=FaqResponse.model_validate(faq), msg="更新成功")
    except ValueError as e:
        raise HTTPException(status_code=400, detail=str(e))


@router.delete("/{faq_id}", response_model=R[None], summary="删除FAQ")
def delete_faq(
    faq_id: int,
    db: Session = Depends(get_db),
    user: User = Depends(require_roles("ADMIN")),
):
    try:
        faq_service.delete_faq(db, faq_id)
        return R.ok(msg="删除成功")
    except ValueError as e:
        raise HTTPException(status_code=400, detail=str(e))
```

### Step 6: 注册路由 `api/router.py`


## 3.9 API 文档规范（Swagger 注解）

所有 API 端点必须编写完整的 Swagger 注解，确保 `/docs` 页面可读性。

### 3.9.1 端点装饰器

```python
@router.get(
    "/{faq_id}",
    response_model=R[FaqResponse],
    summary="查询 FAQ 详情",
    description="根据 ID 查询单条 FAQ 记录",
    responses={
        404: {"description": "FAQ 不存在"},
    },
)
async def get_faq(faq_id: int, db: Session = Depends(get_db)):
    ...
```

### 3.9.2 注解规范

| 参数 | 规范 | 示例 |
|------|------|------|
| `summary` | 简短动词+对象，≤15字 | `"查询 FAQ 详情"` |
| `description` | 补充说明，可选 | `"根据 ID 查询单条 FAQ 记录"` |
| `response_model` | 使用 `R` 或 `PageResult` 包装 | `R[FaqResponse]` |
| `status_code` | POST 创建用 201，其余省略 | `status_code=201` |
| `tags` | 在 `APIRouter(prefix=..., tags=["xxx"])` 中统一设置 | `tags=["FAQ管理"]` |
| `responses` | 非 200 响应说明 | `{404: {"description": "..."}}` |

### 3.9.3 Schema 中的 Field 注解

```python
from pydantic import BaseModel, Field

class FaqCreate(BaseModel):
    question: str = Field(
        min_length=1,
        max_length=500,
        description="问题内容",
        examples=["如何查询库存？"],
    )
    sort_order: int = Field(0, ge=0, description="排序权重，越小越靠前")
```

| Field 参数 | 说明 |
|-----------|------|
| `description` | 字段说明，显示在 Swagger 中 |
| `examples` | 示例值，Swagger 自动展示 |
| `min_length` / `max_length` | 字符串长度限制 |
| `ge` / `le` | 数值范围限制 |
| `default` | 默认值 |

### 3.9.4 全局配置

在 `main.py` 中通过 `app = FastAPI(title="IMS", ...)` 配置全局 Swagger 信息：

```python
app = FastAPI(
```
