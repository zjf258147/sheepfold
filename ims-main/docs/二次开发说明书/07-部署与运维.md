## 7.2 Docker Compose 部署

### 7.2.1 服务架构

```
                    浏览器 :8080
                       │
               ┌───────▼───────┐
               │   frontend    │  Nginx :80 → Vue 静态资源
               └───────┬───────┘
                       │ /api/v1/*
               ┌───────▼───────┐
               │   backend     │  FastAPI :8000
               └───┬───────┬───┘
                   │       │
          ┌────────▼──┐ ┌──▼──────┐
          │   mysql    │ │  redis  │
          │   :3306    │ │  :6379  │
          └────────────┘ └─────────┘
```

### 7.2.2 启动与停止

```bash
# 首次启动
$ cp .env.example .env
$ docker compose up -d --build

# 停止服务
$ docker compose down

# 停止并清除数据（⚠️ 数据库数据会丢失）
$ docker compose down -v
```

### 7.2.3 常用运维命令

```bash
# 查看服务状态
$ docker compose ps

# 查看后端日志
$ docker compose logs -f backend

# 查看前端日志
$ docker compose logs -f frontend

# 进入后端容器
$ docker compose exec backend /bin/bash

# 进入 MySQL
$ docker compose exec mysql mysql -u ims -p ims

# 重启单个服务
$ docker compose restart backend

# 更新部署（拉取新代码后）
$ git pull
$ docker compose up -d --build
```

### 7.2.4 环境变量清单（生产环境必改）

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `MYSQL_ROOT_PASSWORD` | `ims_root_pass` | ⚠️ **必须修改** |
| `MYSQL_PASSWORD` | `ims_pass` | ⚠️ **必须修改** |
| `JWT_SECRET_KEY` | — | ⚠️ **必须修改**为随机长字符串 |
| `ADMIN_PASSWORD` | `<请自行设置强密码>` | ⚠️ **必须修改** |
| `DEBUG` | `false` | 生产环境必须为 `false`（关闭 Swagger） |
| `FRONTEND_PORT` | `8080` | 可自定义 |
| `LOG_LEVEL` | `INFO` | 生产建议 `WARNING` |
| `CORS_ORIGINS` | — | 只允许实际使用的域名 |

### 7.2.5 数据备份

```bash
# 备份 MySQL 数据库
$ docker compose exec mysql mysqldump -u root -p ims > backup_$(date +%Y%m%d).sql

# 恢复数据库
$ docker compose exec -T mysql mysql -u root -p ims < backup_20260101.sql
```

### 7.2.6 数据持久化

Docker Compose 定义了三个数据卷：

| 卷 | 用途 | 清除后果 |
|----|------|---------|
| `mysql_data` | MySQL 数据库文件 | ⚠️ 所有数据丢失 |
| `redis_data` | Redis 持久化数据 | 缓存丢失，不影响主数据 |
| `uploads_data` | Logo 等上传文件 | Logo 丢失 |

> ⚠️ `docker compose down -v` 会清除所有数据卷，生产环境慎用。

## 7.3 本地开发部署

详见第1章"开发环境搭建"。

简要步骤：

```bash
# 后端
$ cd backend
$ cp .env.example .env
$ uv sync
$ uv run alembic upgrade head
$ uv run python scripts/init_admin.py
$ uv run uvicorn main:app --reload

# 前端
$ cd frontend
$ cp .env.example .env
$ npm install
$ npm run dev
```

## 7.4 生产环境检查清单

部署到生产环境前，逐项检查：

- [ ] `.env` 中所有密码/密钥已修改为强密码
- [ ] `DEBUG=false`
- [ ] `JWT_SECRET_KEY` 为随机长字符串（≥32 字符）
- [ ] `CORS_ORIGINS` 只包含实际域名
- [ ] MySQL 使用独立密码，不共用 root 密码
- [ ] 防火墙限制 MySQL (3306) 和 Redis (6379) 仅内网访问
- [ ] 日志级别设为 `WARNING` 或 `ERROR`
- [ ] 数据备份策略已配置（cron 定时备份）
- [ ] 已测试完整部署流程
- [ ] SSL 证书已配置（HTTPS）

## 7.5 故障恢复

### 7.5.1 服务不可用

```bash
# 1. 检查容器状态
$ docker compose ps

# 2. 查看后端日志
$ docker compose logs --tail=50 backend

# 3. 尝试重启
$ docker compose restart backend
$ docker compose restart frontend
```

### 7.5.2 数据库连接失败

检查顺序：
1. MySQL 容器是否运行：`docker compose ps mysql`
2. 能否连接 MySQL：`docker compose exec mysql mysqladmin ping -h 127.0.0.1`
3. `.env` 中连接信息是否正确
4. 后端日志中是否有具体错误

### 7.5.3 前端页面空白

1. 检查前端容器是否运行
2. 检查后端是否正常：`curl http://localhost:8000/health`
3. 浏览器 F12 查看 Console 和 Network 是否有报错
4. 检查 CORS 配置：`.env` 中 `CORS_ORIGINS` 是否包含当前访问域名

### 7.5.4 从数据库备份恢复

```bash
# 停止应用（保留数据库运行）
$ docker compose stop backend frontend

# 恢复数据库
$ docker compose exec -T mysql mysql -u root -p ims < backup.sql

# 重启应用
$ docker compose start backend frontend
```

## 7.6 系统维护脚本

### 7.6.1 初始化管理员

```bash
$ cd backend
$ uv run python scripts/init_admin.py
```

在 `.env` 中配置 `ADMIN_USERNAME` 和 `ADMIN_PASSWORD`，首次启动自动创建。已存在则跳过。

### 7.6.2 生成数据字典

```bash
$ cd backend
$ uv run python scripts/generate_data_dict.py
```

每次修改数据库表结构后执行，生成最新的数据字典。

### 7.6.3 Docker 入口脚本

[backend/scripts/docker-entrypoint.sh](file:///c:/Users/25075/Desktop/IMS生产物料与产品追溯管理系统/ims-main/backend/scripts/docker-entrypoint.sh) — 容器启动时自动执行：
1. 等待 MySQL 就绪
2. 执行 `alembic upgrade head`（数据库迁移）
3. 执行 `init_admin.py`（创建管理员）
4. 启动 uvicorn

## 7.7 版本升级流程

当新版本包含数据库变更时，升级步骤：

```bash
# 1. 备份数据库（重要！）
$ docker compose exec mysql mysqldump -u root -p ims > backup_before_upgrade.sql

# 2. 拉取新代码
$ git pull

# 3. 重新构建并启动（alembic 自动执行迁移）
$ docker compose up -d --build

# 4. 验证
$ docker compose ps
$ curl http://localhost:8000/health
```

> ⚠️ 如果迁移涉及高风险操作（如 `ALTER TABLE` 大表），建议先在测试环境验证。
