# 第9章 二期拓展评估清单

> **文档版本**：v1.0 | **更新日期**：2026-09-10 | **作者**：文档组

本章列出潜在的二期待拓展功能，从**价值、难度、风险**三个维度评估，供技术负责人制定开发计划时参考。

---

## 9.1 评估维度说明

| 维度 | 等级 | 说明 |
|------|:---:|------|
| **业务价值** | ⭐⭐⭐⭐⭐ | 高价值：核心流程优化或新增收入 |
| | ⭐⭐⭐ | 中等价值：提升效率但非必须 |
| | ⭐ | 低价值：锦上添花 |
| **开发难度** | 🔴 高 | 涉及架构变更或多个模块联动 |
| | 🟡 中 | 需要 3~10 天开发 |
| | 🟢 低 | 1~3 天可完成 |
| **风险** | ⚠️ 高 | 可能影响现有数据或核心流程 |
| | ⚠️ 中 | 独立模块，影响可控 |
| | ⚠️ 低 | 纯新增，不影响现有功能 |

## 9.2 功能评估表

### 9.2.1 核心流程增强

| 功能 | 价值 | 难度 | 风险 | 说明 |
|------|:---:|:---:|:---:|------|
| 生产任务与工序管理 | ⭐⭐⭐⭐⭐ | 🔴 | ⚠️ | 当前 `ProductionTask` 表已建，完善工序分配、工时统计 |
| 品质检验数字化 | ⭐⭐⭐⭐ | 🟡 | ⚠️ | 完善来料检/RMA质检的检测项、标准值、判定规则 |
| 多仓库支持 | ⭐⭐⭐⭐ | 🔴 | ⚠️ | 当前为单仓库模型，需改造库存/入库/出库全部模块 |
| 库存预警（安全库存） | ⭐⭐⭐ | 🟢 | ⚠️ | 在 SKU 上添加 `alert_threshold`，仪表盘展示预警 |

| 功能 | 价值 | 难度 | 风险 | 说明 |

## 9.3 推荐优先级（建议排序）

| 优先级 | 功能 | 理由 |
|:---:|------|------|
| **P0** | 生产任务与工序管理 | 模型已有基础，完善后可打通 BOM→生产→质检→入库 |
| **P0** | 批量操作 | 投入小回报大，提升操作效率 |
| **P1** | 品质检验数字化 | 提升质量控制能力 |
| **P1** | 库存预警 | 实现简单，预防性价值大 |
| **P1** | 高级报表 | 提升数据利用价值 |
| **P2** | 多仓库支持 | 架构改动大，需详细设计 |
| **P2** | 对接 ERP | 集成难度高，需专门立项 |
| **P2** | 数据权限 | 改动范围大 |
| **P3** | 移动端/数据大屏/SSO | 特定场景需求 |

---

## 9.4 评估建议

1. **优先做低难度、高价值的功能**（如批量操作、库存预警），快速交付
2. **高难度功能先做 POC**（如多仓库、ERP对接），验证可行性再全面开发
3. **跨模块变更（9.2.1 类）需全量回归测试**，参考第6章测试规范
4. **每个功能上线后更新本文档**，记录实际工时和遇到的问题
