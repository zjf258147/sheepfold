# 第8章 常见二次开发场景

> **文档版本**：v1.0 | **更新日期**：2026-09-10 | **作者**：文档组

本章列举二次开发中最常见的场景，按"需求 → 影响范围 → 实施步骤"组织，供开发者快速定位和参照。

## 8.1 新增一个业务模块

**场景**：新增一个独立业务模块（如"客户投诉管理"）。

**影响范围**：

| 层 | 新建文件 | 修改文件 |
|----|---------|---------|
| 后端 models | `models/complaint.py` | `models/__init__.py` |
| 后端 schemas | `schemas/complaint.py` | — |
| 后端 service | `service/complaint_service.py` | `service/__init__.py` |
| 后端 api | `api/complaint.py` | `api/router.py` |
| 前端 api | `api/complaint.js` | — |
| 前端 view | `views/Complaint.vue` | — |
| 前端 router | — | `router/index.js` |
| 前端 menu | — | `layout/MainLayout.vue` |
| 数据字典 | — | 运行 `generate_data_dict.py` |

**实施步骤**：参照第3章 3.8 节（后端）和第4章 4.10 节（前端）的完整示例。

## 8.2 在现有模块中新增字段

**场景**：来料管理中新增"供应商批次号"字段。

**影响范围**：

| 步骤 | 文件 | 操作 |
|:---:|------|------|
| 1 | `models/incoming.py` | 添加 `batch_no` 字段（必须写 `comment`） |
| 2 | `schemas/incoming.py` | 在 Create/Update/Response 中添加字段 |
| 3 | `service/incoming_service.py` | 处理新字段的存储逻辑 |
| 4 | — | `alembic revision --autogenerate -m "add batch_no to incoming"` |
| 5 | — | `alembic upgrade head` |
| 6 | — | 运行 `generate_data_dict.py` |
| 7 | `views/IncomingReceipt.vue` | 表单和表格中添加字段 |
| 8 | `constants/enums.js` | 如需枚举则添加 |

> ⚠️ 新增字段后必须重新生成数据字典，否则文档与代码不一致。

## 8.3 新增状态/流程节点

**场景**：返厂维修中新增"待客户确认"状态。

**影响范围**：

| 步骤 | 文件 | 操作 |
|:---:|------|------|
| 1 | `models/enums.py` | 添加 `RmaStatus.AWAITING_CUSTOMER` 枚举 |
| 2 | `models/enums.py` | 添加 `RMA_STATUS_MAP` 中的中文映射 |
| 3 | `service/rma_service.py` | 修改状态流转逻辑 |
| 4 | `constants/enums.js` | 添加前端枚举 + Tag 颜色 |
| 5 | `views/RmaReturn.vue` | 更新状态展示和操作按钮 |

**状态流转修改要点**：

- 检查所有状态流转的路由是否正确（哪些状态可以到新状态，哪些不能）
- 检查新旧状态的过渡路径（例如从"维修中"到"待客户确认"再到"维修完成"）
- 更新 `rma_service.py` 中的状态校验逻辑

**场景**：新增"财务"角色，可查看所有订单但不可操作。

## 8.5 新增 Excel 导入导出

**场景**：入库单支持 Excel 批量导入。

**影响范围**：

| 步骤 | 文件 | 操作 |
|:---:|------|------|
| 1 | `utils/excel_import.py` | 添加 `parse_inbound_import` 解析函数 |
| 2 | `utils/excel_export.py` | 添加 `build_inbound_template` 模板函数 |
| 3 | `api/inbound.py` | 添加 `POST /import` 和 `GET /template` 端点 |
| 4 | `api/inbound.js` | 添加前端上传/下载函数 |
| 5 | `views/Inbound.vue` | 添加"导入"按钮和文件上传组件 |

**Excel 导出关键代码**：

```python
from app.utils.excel_export import build_simple_xlsx
from io import BytesIO

def export_orders(db: Session) -> tuple[BytesIO, str]:
    orders = db.query(MyModel).all()
    rows = [[o.id, o.name, o.status, o.created_at] for o in orders]
    headers = ["ID", "名称", "状态", "创建时间"]
    buffer = build_simple_xlsx(rows, headers)
    return buffer, "export.xlsx"
```

## 8.9 跨模块影响的变更

以下类型的变更是跨模块的，需要额外注意：

| 变更类型 | 需要检查的模块 |
|---------|-------------|
| 修改 `enums.py` 中的枚举 | 所有依赖该枚举的 model、service、api、前端 enum.js |
| 修改 `TimestampMixin` / `Base` | **所有**模型（39+ 表） |
| 修改 `R` / `PageResult` | 所有 api 端点 |
| 修改 `request.js` 拦截器 | 所有前端 API 调用 |
| 修改路由守卫 | 所有页面 |
| 修改数据库连接配置 | 所有 service、alembic |

> 💡 跨模块变更前，先用 `Grep` 搜索所有引用该组件的位置，逐个评估影响。

## 9.1 评估维度说明

| 维度 | 等级 | 说明 |
|------|:---:|------|
| **业务价值** | ⭐⭐⭐⭐⭐ | 高价值：核心流程优化或新增收入 |
| | ⭐⭐⭐ | 中等价值：提升效率但非必须 |
| | ⭐ | 低价值：锦上添花 |
| **开发难度** | 🔴 高 | 涉及架构变更或多个模块联动 |
| | 🟡 中 | 需要 3~10 天开发 |
| | 🟢 低 | 1~3 天可完成 |
| **风险** | ⚠️ 高 | 可能影响现有数据或核心流程 |
| | ⚠️ 中 | 独立模块，影响可控 |
| | ⚠️ 低 | 纯新增，不影响现有功能 |

## 9.3 推荐优先级（建议排序）

| 优先级 | 功能 | 理由 |
|:---:|------|------|
| **P0** | 生产任务与工序管理 | 模型已有基础，完善后可打通 BOM→生产→质检→入库 |
| **P0** | 批量操作 | 投入小回报大，提升操作效率 |
| **P1** | 品质检验数字化 | 提升质量控制能力 |
| **P1** | 库存预警 | 实现简单，预防性价值大 |
| **P1** | 高级报表 | 提升数据利用价值 |
| **P2** | 多仓库支持 | 架构改动大，需详细设计 |
| **P2** | 对接 ERP | 集成难度高，需专门立项 |
| **P2** | 数据权限 | 改动范围大 |
| **P3** | 移动端/数据大屏/SSO | 特定场景需求 |

---

## 9.4 评估建议

1. **优先做低难度、高价值的功能**（如批量操作、库存预警），快速交付
2. **高难度功能先做 POC**（如多仓库、ERP对接），验证可行性再全面开发
3. **跨模块变更（9.2.1 类）需全量回归测试**，参考第6章测试规范
4. **每个功能上线后更新本文档**，记录实际工时和遇到的问题
