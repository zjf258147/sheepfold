# 第11章 代码质量检查

> **文档版本**：v1.1 | **更新日期**：2026-09-11 | **作者**：文档组

本章提供一套代码质量检查清单，每次提交代码前逐项自查。

---

## 11.1 后端检查清单

### 11.1.1 模型层（Models）

- [ ] 所有 `mapped_column` 都写了 `comment`
- [ ] 主键使用 `BigInteger` + `autoincrement=True`
- [ ] 必填字段设置了 `nullable=False`
- [ ] 可选字段类型使用了 `| None`（如 `Mapped[str | None]`）
- [ ] 外键写了 `ForeignKey("table.column")`
- [ ] 枚举/状态列加了 `index=True`
- [ ] 金额字段使用 `Numeric(12, 2)`
- [ ] 关联关系使用了正确的 `back_populates` 和 `cascade`
- [ ] 新模型在 `models/__init__.py` 中 import（确保 alembic 能发现）

### 11.1.2 Schema 层（Schemas）

- [ ] Response Schema 设置了 `model_config = {"from_attributes": True}`
- [ ] Create/Update Schema 的字段有适当的 `Field` 约束（`min_length`、`max_length`、`gt`、`le`）
- [ ] Schema 文件与 model/api 文件同名（如 `inbound.py`）
- [ ] 响应使用 `R[T]` 泛型包装

### 11.1.3 Service 层（Service）

- [ ] 函数第一个参数是 `db: Session`
- [ ] 不手动调用 `db.commit()`（用 `db.flush()` 代替）
- [ ] 列表查询必须分页（不允许 `.all()`）
- [ ] 使用了 `joinedload` 预加载关联（避免 N+1）
- [ ] 错误通过抛出 `ValueError` / `RuntimeError` 传递，不直接返回错误字符串
- [ ] 日志记录了关键操作和异常信息

### 11.1.4 API 层（API）

- [ ] 所有端点有 `summary`（Swagger 文档）
- [ ] 需要认证的端点有 `Depends(get_current_user)`
- [ ] 需要权限的端点使用了 `require_roles(...)`
- [ ] 查询参数使用了 `Query()` 添加校验和说明
- [ ] 创建/更新/删除等写操作记录了审计日志
- [ ] 异常通过 `HTTPException` 返回
- [ ] 新路由在 `router.py` 中注册
- [ ] `response_model` 中的泛型类型写完整

### 11.1.5 数据库迁移

- [ ] 修改模型后执行了 `alembic revision --autogenerate`
- [ ] 检查了生成的迁移文件是否正确
- [ ] 执行了 `alembic upgrade head`
- [ ] 运行了 `generate_data_dict.py` 更新数据字典

## 11.2 前端检查清单

### 11.2.1 API 封装

- [ ] API 函数命名与后端端点对应（`listXxx` / `createXxx` / `updateXxx` / `deleteXxx`）
- [ ] URL 路径正确（注意 `/api/v1/` 前缀）
- [ ] 文件下载使用了 `responseType: 'blob'`

### 11.2.2 页面组件

- [ ] 使用 `<script setup>` 语法
- [ ] 数据加载有 `v-loading` 状态
- [ ] 列表页有分页组件
- [ ] 表单有验证规则（`el-form` + `rules`）
- [ ] 删除/危险操作有确认弹窗（`ElMessageBox.confirm`）
- [ ] 编辑时表单数据是副本（`{ ...row }`），不会直接修改表格数据
- [ ] 异步操作有 try/catch 和 loading 状态

### 11.2.3 路由与菜单

- [ ] 路由 `meta.roles` 或 `meta.admin` 配置正确
- [ ] 菜单 `allMenus` 的角色配置与路由一致
- [ ] 页面有 `meta.title`

## 11.3 通用检查清单

### 11.3.1 代码风格

- [ ] 没有无用的注释（TODO/FIXME 有具体说明）
- [ ] 没有 `console.log` 调试代码
- [ ] 没有硬编码的配置值（使用 `.env` 或常量）
- [ ] 导入语句按层级分组（标准库 → 第三方 → 项目内）

### 11.3.2 安全

- [ ] 密码不经过明文存储或日志
- [ ] Token 不写入 URL
- [ ] `.env` 文件不在 Git 中（`.gitignore` 已配置）
- [ ] Swagger 在生产环境已关闭（`DEBUG=false`）

### 11.3.3 文档

- [ ] 数据字典已重新生成（如有表结构变更）
- [ ] 新增/修改的功能在《二次开发说明书》中已更新
- [ ] API 的 `summary` 写清楚功能

## 11.4 快速自查命令

```bash
# 后端
$ cd backend
$ uv run python scripts/generate_data_dict.py   # 数据字典
$ uv run alembic check                           # 迁移状态
$ uv run python -c "import app.models"           # 模型导入检查

# 前端
$ cd frontend
$ npm run build                                  # 构建检查（会报错提示）
$ npm test                                       # 测试
```

## 11.5 复杂度检查

以下情况需要警惕过度设计：

| 信号 | 建议 |
|------|------|
| 一个函数超过 50 行 | 拆分为多个小函数 |
| 一个文件超过 500 行 | 拆分为多个模块 |
| 嵌套 if 超过 3 层 | 使用提前返回（early return）简化 |
| 函数参数超过 6 个 | 考虑用 Pydantic Schema 包装 |
