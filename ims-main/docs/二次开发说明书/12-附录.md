## 附录D 编号前缀速查表

系统所有业务单号遵循统一格式：`前缀{YYYYMMDD}{序号}`，由 [backend/app/utils/order_no.py](file:///c:/Users/25075/Desktop/IMS生产物料与产品追溯管理系统/ims-main/backend/app/utils/order_no.py) 统一生成。

| 前缀 | 格式 | 业务含义 | 所属主线 |
|:---:|------|------|:---:|
| `RC` | RC{YYYYMMDD}{序号3位} | 到货单号 | A |
| `FC` | FC{YYYYMMDD}{序号3位} | 返厂单号 | B |
| `SH` | SH{YYYYMMDD}{序号3位} | 出货单号 | — |
| `BF` | BF{YYYYMMDD}{序号3位} | 报废单号 | B |
| `WX` | WX{YYYYMMDD}{序号3位} | 维修工单号 | B |
| `DG` | DG{YYYYMMDD}{序号3位} | 诊断编号 | B |
| `RH` | RH{YYYYMMDD}{序号3位} | 再出货单号 | B |
| `JIN` | JIN-{YYYYMMDD}-{序号4位} | 入库单号 | — |
| `JOUT` | JOUT-{YYYYMMDD}-{序号4位} | 出库单号 | — |
| `BOM` | BOM{YYYYMMDD}{序号3位} | BOM编号 | D |
| `PR` | PR{YYYYMMDD}{序号3位} | 生产任务编号 | D |

> ⚠️ `JIN` 和 `JOUT` 使用连字符格式（`JIN-20260911-0001`），其余使用直连格式（`RC20260911001`）。

## 附录F 常见错误代码

### HTTP 状态码（FastAPI 自动抛出）

| 状态码 | 含义 | 触发场景 |
|:---:|------|---------|
| 200 | 成功 | 正常响应（包括业务错误 `R.fail()`） |
| 201 | 已创建 | POST 创建资源成功 |
| 400 | 请求错误 | 参数校验失败、业务规则不满足 |
| 401 | 未认证 | Token 缺失、过期、无效 |
| 403 | 无权限 | 角色不满足 `require_roles` 要求 |
| 404 | 未找到 | 资源 ID 不存在 |
| 409 | 冲突 | 唯一键重复、状态不允许操作 |
| 422 | 校验失败 | Pydantic 请求体校验失败（FastAPI 自动） |
| 500 | 服务器错误 | 未捕获的异常 |

### 业务响应码（R.code）

| code | 含义 |
|:---:|------|
| `0` | 成功（`R.ok()`） |
| `-1` | 通用失败（`R.fail()` 默认） |
| 自定义 | 可在调用 `R.fail(code=N)` 时传入 |

> 💡 `R.fail()` 的 HTTP 状态码仍为 200，通过 `code` 字段区分业务成功/失败。认证/权限类错误使用 `HTTPException` 抛 401/403。
