## 二、Markdown 编写规范

### 2.1 标题层级

```markdown
# 一级标题：文档标题（每个 .md 文件只有一个）
## 二级标题：章标题
### 三级标题：节标题
#### 四级标题：小节标题（尽量不超过四级）
```

**规则**：
- 每个 `.md` 文件只有一个 `#` 一级标题
- 标题层级不超过四级，超过时考虑拆分文件
- 标题编号使用数字（如 `## 4.1 主线A：采购来料管理`）
- 标题后紧跟一个空行

### 2.2 段落与换行

- 段落之间空一行
- 中文段落不使用缩进
- 重要提示使用 `⚠️` 前缀，加粗
- 行内代码使用反引号：`` `PENDING_INSPECTION` ``

### 2.3 表格

```markdown
| 字段名 | 类型 | 必填 | 默认值 | 说明 |
|--------|------|:---:|--------|------|
| id | Integer | ✅ | 自增 | 主键 |
| item_sn | String(50) | ✅ | — | 单品SN，唯一 |
```

**规则**：
- 表头与内容用 `|` 分隔，对齐线用 `-`
- 居中对齐用 `:---:`，左对齐用 `:---`，右对齐用 `---:`
- 必填列用 ✅/❌
- 空值用 `—` 表示
- 表格前后各空一行

### 2.4 代码块

````markdown
```python
# 代码示例
def example():
    pass
```
````

```markdown
# 命令行示例
```bash
python scripts/generate_data_dict.py > docs/数据字典.md
```
```

**规则**：
- 必须标注语言类型（python/bash/sql/json/yaml）
- 代码块前后各空一行
- 长命令可换行，用 `\` 续行

### 2.5 列表

```markdown
- 无序列表项
- 无序列表项
  - 嵌套子项（缩进2个空格）

1. 有序列表项
2. 有序列表项
   1. 嵌套子项（缩进3个空格）
```

**规则**：
- 无序列表用 `-`，不用 `*`
- 嵌套缩进2个空格
- 列表项之间一般不空行，除非列表项内容超过3行

### 2.6 强调

```markdown
**加粗**：用于关键术语、按钮名称、重要提示
*斜体*：用于英文术语、注释
`代码`：用于字段名、状态值、文件路径、命令
```

**规则**：
- 按钮名称用加粗：**新增**、**保存**、**提交**
- 状态值用代码：`PENDING_INSPECTION`、`IN_STOCK`
- 字段名用代码：`item_sn`、`sku_code`
- 文件路径用代码：`backend/scripts/generate_data_dict.py`

### 2.7 链接与引用

```markdown
[链接文字](相对路径/文件名.md)
[链接文字](相对路径/文件名.md#章节标题)
```

**规则**：
- 文档内部跳转用相对路径
- 不要使用绝对路径
- 外部链接必须可访问

### 2.8 图片

```markdown
![图片描述](images/截图名称.png)
```

**规则**：
- 图片统一放在各文档目录下的 `images/` 文件夹
- 截图统一使用 PNG 格式
- 命名规则：`模块-功能-描述.png`（如 `incoming-检验报告-填写界面.png`）
- 图片描述必须写，不可为空
- 截图分辨率：建议 1920×1080，必要时裁剪

### 2.9 Mermaid 图表

````markdown
```mermaid
stateDiagram-v2
    [*] --> PENDING: 创建
    PENDING --> DONE: 完成
    DONE --> [*]
```
````

**规则**：
- 所有流程图、状态图使用 Mermaid 语法
- 图表前后各空一行
- 状态节点名用大写字母 + 下划线
- 状态值用代码中的实际枚举值

### 2.10 提示框

```markdown
> **⚠️ 注意**：这是重要提示内容。
> 可以多行。

> **📊 核心指标**：待检验数量、不合格率
```

**规则**：
- 使用引用块 `>` 表示提示
- `⚠️` 用于警告/注意事项
- `📊` 用于指标/数据
- `💡` 用于技巧/建议
- `❌` 用于禁止/错误操作

## 三、文档内容规范

### 3.1 语言风格

| 项目 | 规范 |
|------|------|
| 语言 | 简体中文 |
| 语气 | 客观、专业、简洁 |
| 人称 | 避免"我"、"你"，用"用户"、"操作者"或直接省略 |
| 时态 | 一般现在时 |
| 术语 | 首次出现加英文全称，如：SN（Serial Number，序列号） |

### 3.2 操作步骤写法

```markdown
**步骤1：操作标题**

1. 进入"模块名"→ 点击 **按钮名**
2. 选择下拉项 → 填写输入框
3. 点击 **提交** → 状态变为 `NEW_STATUS`
```

**规则**：
- 每个步骤以 `**步骤N：标题**` 开头
- 操作路径用 `→` 连接
- 按钮名称加粗
- 结果用 `→` 引出状态变化
- 每个步骤控制在3-7个小步骤

### 3.3 数据表说明写法

**原则**：字段定义以《数据字典》为单一数据源，文档中不手写完整字段表格。

**正确写法**（引用数据字典）：

```markdown
#### X.X.X 表名

> 完整字段定义（类型、必填、默认值）详见《数据字典》→ 模块名 → 表名。

**业务用途**：描述表的业务含义、使用场景。

**关键字段**：`status`（状态控制流转）、`sn`（一物一码关联库存）等。
```

**禁止写法**（手写字段类型表）：

```markdown
# ❌ 禁止：在系统说明书和操作手册中手写字段类型表
| 字段 | 类型 | 必填 | 说明 |
|------|------|:---:|------|
| `field1` | String(50) | ✅ | ... |
```

**例外**：数据字典本身的生成脚本内部可使用表格。

### 3.4 状态枚举说明写法

```markdown
| 状态值 | 含义 | 可执行操作 |
|--------|------|-----------|
| `PENDING` | 待处理 | 编辑、提交 |
| `DONE` | 已完成 | 查看 |
```

### 3.5 注意事项写法

```markdown
#### X.X.X 注意事项

- ⚠️ 入库确认后库存立即生效，不可撤销
- ⚠️ 退货数量不能超过到货数量，系统自动校验
- 💡 批量操作时建议先导出确认数据
```

## 七、二次开发说明书专属规范

> 本章适用于《二次开发说明书》的编写。编写者（含 Trae）必须在遵循第二章~第五章通用规范的基础上，额外遵守本章规定。

### 7.1 代码片段引用规范

二次开发说明书大量引用项目源代码，必须遵循以下规则：

| 规则 | 说明 |
|------|------|
| 短代码（≤30行） | 直接粘贴完整代码块 |
| 长代码（>30行） | 只粘贴关键行，并在代码块上方注明完整文件路径 |
| 引用已有代码 | 使用文件路径 + 行号引用，不重复粘贴 |

```markdown
# 短代码示例（≤30行）

```python
# backend/app/core/deps.py
async def get_current_user(...) -> User:
    """获取当前登录用户。"""
    ...

# 长代码示例（>30行，只贴关键行）

完整文件：`backend/app/api/inbound.py`

```python
@router.post("/inbound-orders", response_model=R)
@require_roles(["WAREHOUSE"])
async def create_inbound_order(...):
    """创建入库单。"""
    ...
```

# 引用已有代码

> 权限校验逻辑详见 `backend/app/core/deps.py:89-105`，此处不赘述。
```

**规则**：
- 文件路径必须以项目根目录下的相对路径开头（如 `backend/app/...`）
- 行号引用格式：`文件名:Lstart-Lend`
- 不重复粘贴已在其他章节出现过的代码

### 7.2 API 接口文档格式

API 接口统一使用以下表格格式：

```markdown
### POST /api/v1/inbound-orders

| 属性 | 值 |
|------|-----|
| 方法 | `POST` |
| 路径 | `/api/v1/inbound-orders` |
| 权限 | `WAREHOUSE` |
| 请求体 | `InboundOrderCreate` |
| 响应体 | `R[InboundOrderOut]` |
| 说明 | 创建入库单 |

**请求体示例**：

```json
{
    "order_no": "JIN-20240910-001",
    "inbound_mode": "PROCUREMENT",
    "partner_id": 1,
    "stock_condition": "QUALIFIED",
    "lines": [...]
}
```

**响应体示例**：

```json
{
    "code": 0,
    "message": "ok",
    "data": { "id": 1, "order_no": "JIN-20240910-001", ... }
}
```
```

**规则**：
- 每个接口独立一个三级标题（`###`）
- 属性表七行：方法、路径、权限、请求体、响应体、说明
- 请求体/响应体 Schema 名称使用代码格式
- 响应体使用 `R[...]` 包裹表示统一响应格式
- 权限列写角色枚举值（如 `WAREHOUSE`），多个用逗号分隔
- JSON 示例必须语法正确，使用真实的字段名

### 7.3 数据库表结构格式

完整表结构使用五列表格（与数据字典格式一致）：

```markdown
### 表：inbound_order（入库单）

| 字段名 | 类型 | 必填 | 默认值 | 说明 |
|--------|------|:---:|--------|------|
| `id` | BIGINT | ✅ | 自增 | 主键 |
| `order_no` | VARCHAR(30) | ✅ | — | JIN-单号 |
| `status` | VARCHAR(20) | ✅ | `INITIATED` | 操作状态 |
```

**与《系统说明书》的边界**：
- 《系统说明书》列**核心表 + 关键字段**（三列：表名、说明、关键字段）
- 《二次开发说明书》列**完整字段**（五列表格），并注明"业务含义详见《系统说明书》第X章"

### 7.4 文件路径引用规范

| 规则 | 示例 |
|------|------|
| 统一使用项目内相对路径 | `backend/app/models/enums.py` |
| 不加盘符或 `~/` | ❌ `C:\...` ✅ `backend/app/...` |
| 前端路径同理 | `frontend/src/views/inbound/InboundList.vue` |
| 行号用冒号分隔 | `backend/app/core/deps.py:89-105` |
| 目录路径末尾不加 `/` | `backend/app/api/` |

### 7.5 命令行示例规范

```markdown
# 在当前目录执行
$ python scripts/generate_data_dict.py

# 在指定目录执行
$ cd backend
$ alembic upgrade head

# 带参数
$ python scripts/generate_data_dict.py --output ../docs/附录/数据字典.md
```

**规则**：
- 每条命令以 `$` 开头
- 需要切换目录时，单独一行 `$ cd 目录名`，不合并为 `$ cd xxx && cmd`
- 命令执行目录在代码块上方用文字标注
- 预期输出紧跟在命令后，不加 `$` 前缀

### 7.7 与《系统说明书》的引用方式

二次开发说明书通过以下两种方式引用《系统说明书》，避免内容重复：

**方式一：章节引用**（适用于业务概念）

```markdown
> 主线A"采购来料管理"的业务流程、角色定义、状态流转详见《系统说明书》第4.1节。
> 本文档仅描述其技术实现。
```

**方式二：技术差异补充**（适用于数据模型、状态枚举）

```markdown
> 《系统说明书》第4.1节已描述主线A的核心业务表，本文档补充完整字段定义及关联关系。
```

**规则**：
- 不复制《系统说明书》中已有的业务描述、流程图、状态说明
- 只写技术实现细节：代码结构、Model 定义、API 接口、数据库设计
- 首次引用时写完整章节号（如"第4.1节"）
- 同一章节多次引用时，后续可简写为"见系统说明书"
