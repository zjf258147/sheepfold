## 二、脚本层修复（`backend/scripts/generate_data_dict.py`）

### ②① 去重 —— 防止表重复输出（P0）

**根因**

`_discover_models()` 遍历 `app/models/*.py` 每个模块文件，但某些模块 `import` 了其他模块的模型类（如 `inbound.py` 中 `from app.models.partner import Partner`），导致同一个类在多个模块中都被 `inspect.getmembers()` 发现。

```
partner      → inbound.py (import) + outbound.py (import) + partner.py (定义) = 3次
product_sku  → inbound.py (import) + product.py (定义) = 2次
```

**修复方式**

在 `_discover_models()` 中增加 `seen_tables` set，按 `__tablename__` 去重，只保留首次发现的类。跳过重复表时用 `DEBUG` 级别记录日志（默认不显示），便于排查同名冲突。

```python
import logging
logger = logging.getLogger(__name__)

def _discover_models() -> list[type]:
    import app.models
    pkg_path = os.path.dirname(app.models.__file__)
    models: list[type] = []
    seen_tables: set[str] = set()

    for _, name, is_pkg in pkgutil.iter_modules([pkg_path]):
        # ... 省略不变的部分 ...

        for _, obj in inspect.getmembers(mod, inspect.isclass):
            # ... 省略不变的部分 ...
            if issubclass(obj, Base):
                table_name = obj.__tablename__
                if table_name in seen_tables:
                    logger.debug(f"跳过已处理的表: {table_name}（来源: {mod.__name__}）")
                    continue
                seen_tables.add(table_name)
                models.append(obj)

    logger.info(f"共发现 {len(models)} 个唯一模型（已去重）")
    return models
```

# === 步骤2：检查 product_sku 只出现1次 ===

### ②② 枚举默认值 —— 输出 `.value` 而非 Python 对象（P0）

**根因**

模型定义 `default=BomStatus.DRAFT`，SQLAlchemy 将 `col.default.arg` 存为 `<BomStatus.DRAFT: 'DRAFT'>`，直接 `str()` 得到 `BomStatus.DRAFT`。

```python
# 模型定义
status: Mapped[str] = mapped_column(String(30), default=BomStatus.DRAFT, nullable=False)

# col.default.arg → <BomStatus.DRAFT: 'DRAFT'>
# str(col.default.arg) → "BomStatus.DRAFT"  ❌ 错误
# col.default.arg.value → "DRAFT"           ✅ 正确
```

**修复方式**

在 `_extract_columns()` 的默认值提取逻辑中增加枚举判断，并确保 `col.default` 可能为 `None` 的分支已被前置逻辑处理：

```python
# 在 col.default 处理分支中，将：
default_str = str(col.default.arg)

# 改为（确保 col.default 非 None 才访问 .arg）：
if col.default is not None and isinstance(col.default.arg, enum.Enum):
    default_str = col.default.arg.value
elif col.default is not None:
    default_str = str(col.default.arg)
```

**影响范围**

| 表 | 字段 | 当前显示 | 修复后 |
|----|------|---------|--------|
| `bom_header` | `status` | `BomStatus.DRAFT` | `DRAFT` |
| `production_task` | `status` | `TaskStatus.PENDING` | `PENDING` |
| `production_task` | `material_availability` | `MaterialAvailability.SHORTAGE` | `SHORTAGE` |

### ②③ 字段类型标注 —— 类型列只显示类型，说明列标注继承（P1）

**根因**

当前写法把继承信息拼到类型列：

```python
type_str = field_type + "（继承）" if is_ts else field_type
```

导致类型列显示 `DATETIME（继承）`，阅读体验差。

**修复方式**

类型列只显示纯类型，将 "继承自 TimestampMixin" 追加到说明列：

```python
# 类型列
type_str = field_type  # 只显示 DATETIME

# 说明列
comment = col.comment or ""
if is_ts:
    suffix = "继承自 TimestampMixin"
    comment = f"{comment}（{suffix}）" if comment else suffix
```

### ②④ 复合主键默认值 —— 显示"联合主键"而非"自增"（P1）

**根因**

当前逻辑：`col.primary_key and col.autoincrement` → "自增"。但复合主键（如 `inventory_sku_daily_ledger` 的 `snapshot_date + sku_id`）的 `autoincrement` 属性可能被 SQLAlchemy 误判或设为特殊值。

**修复方式**

先判断表是否复合主键，若是则显示"联合主键"：

```python
# 判断是否为复合主键（顺序重要：先判断复合主键）
pk_columns = list(col.table.primary_key.columns)
is_composite_pk = len(pk_columns) > 1

if is_pk and is_composite_pk:
    default_str = "联合主键"
elif is_pk and col.autoincrement is True:
    default_str = "自增"
elif is_pk and col.autoincrement == "auto":
    default_str = "自增"
else:
    default_str = "—"
```

**验证方法**

```bash
# === 步骤1：重新生成数据字典 ===
cd backend
uv run python scripts/generate_data_dict.py

# === 步骤2：查看 inventory_sku_daily_ledger 表定义 ===
Select-String -Path "docs/附录/数据字典.md" -Pattern "inventory_sku_daily_ledger" -Context 0,15
# 预期：snapshot_date 和 sku_id 的默认值列显示 "联合主键"
#       id 字段（如果有的话）的默认值列显示 "—"

# === 步骤3：用 Python 确认表的主键结构 ===
uv run python -c "
from app.db.base import Base
import app.models
table = Base.metadata.tables['inventory_sku_daily_ledger']
pk_cols = [c.name for c in table.primary_key.columns]
print(f'主键列: {pk_cols}')
print(f'主键数量: {len(pk_cols)}')
# 预期：主键数量 > 1（复合主键）
"

# === 步骤4：确认其他单主键表不受影响 ===
Select-String -Path "docs/附录/数据字典.md" -Pattern "inbound_order" -Context 0,15
# 预期：id 字段的默认值列仍显示 "自增"
```

### ③① `inbound_order` 缺少 `change_reason` 字段（P0）

**文件**：`backend/app/models/inbound.py`

**问题**：其他所有业务表都有 `change_reason`，唯独 `inbound_order` 没有。

**修复方式**

在 `InboundOrder` 类中新增：

```python
change_reason: Mapped[str | None] = mapped_column(
    String(255), nullable=True, comment="变更原因"
)
```

然后执行数据库迁移：

```bash
cd backend
uv run alembic revision --autogenerate -m "add change_reason to inbound_order"
uv run alembic upgrade head
```

**迁移后回填**

```sql
-- 为现有记录统一回填默认值
UPDATE inbound_order SET change_reason = '历史数据' WHERE change_reason IS NULL;
```

**API 层同步检查**

```bash
# 检查 inbound 的 Schema 是否需要接受 change_reason
Select-String -Path "backend/app/schemas/inbound*.py" -Pattern "change_reason"
# 如果 Create/Update Schema 中已有 change_reason → 无需修改
# 如果没有 → 考虑是否需要 API 层支持传入该字段
```

**验证方法**
