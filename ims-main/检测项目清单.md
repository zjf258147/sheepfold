### 2.5 Capacitor 专项检查（二期新增）

> **设计原则**：Capacitor 打包现有 Web = 零额外开发。App 只放"现场高频、需扫码/拍照"的操作，复杂报表/BOM编辑/批量导入导出不放。

#### 2.5.1 架构设计

```
┌─────────────────────────────────────────────┐
│              Android APK                     │
│  ┌───────────────────────────────────────┐  │
│  │         Capacitor WebView              │  │
│  │  ┌─────────────────────────────────┐  │  │
│  │  │    Vue 3 + Element Plus SPA     │  │  │
│  │  │    (Vite 构建 → dist/)           │  │  │
│  │  │                                 │  │  │
│  │  │  axios → /api/v1/*              │  │  │
│  │  └──────────────┬──────────────────┘  │  │
│  └─────────────────┼─────────────────────┘  │
└────────────────────┼────────────────────────┘
                     │ HTTP (cleartext)
                     ▼
         ┌───────────────────┐
         │  FastAPI Backend  │
         │  (port 8000)      │
         └───────────────────┘
```

**方案决策：打包静态资源（方案A）**

| 方案 | 配置 | 优点 | 缺点 | 选择 |
|------|------|------|------|:---:|
| A. 打包静态资源 | `webDir: "dist"`，不配 `server.url` | 离线可用，启动快 | 每次更新需重新打包 | ✅ |
| B. 加载服务器页面 | 配 `server.url: "http://IP:8080"` | 更新即生效，无需重打包 | 必须联网，启动稍慢 | ❌ |

> 理由：内网环境更新不频繁；离线可用，现场信号不好时也能操作；更新时重新发 APK，员工覆盖安装即可。

#### 2.5.2 6 阶段推进计划

| 阶段 | 内容 | 产出 | 依赖 | 状态 |
|:---:|------|------|------|:---:|
| 1 | 环境准备：Android Studio + SDK（API 26+）+ 环境变量 `ANDROID_HOME` | 开发环境就绪 | 开发机 | ⬜ |
| 2 | 生成 Android 项目：`npm run cap:add:android` → `cap:sync` → `cap:open` | `android/` 目录 + 首次构建成功 | 阶段1 | ⬜ |
| 3 | 功能适配：明确 App 功能范围，只放现场高频操作 | 功能清单确认 | 阶段2 | ⬜ |
| 4 | 原生插件集成：preferences / status-bar / camera（3个） | 插件安装完成 | 阶段1 | ⬜ |
